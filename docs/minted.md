# minted code

[Documentation](README.md) · [Editing features](editing.md)

`\mintinline[options]{language}{code}` and `\mint[options]{language}{code}` support command completion, fragment and header signature help. Pairs of character delimiters can also be used, such as `\mintinline{python}|print("Hello")|`. Code is highlighted as verbatim text, and tags, commands, references, and file paths within it are not entered into the LaTeX index and are not renamed. The text after the end of the code continues to be parsed normally. Confirmable pure static forwarding, stable command replication and its chaining in the current source file also retain the same code boundaries; real declarations and calls of aliases can be renamed, and control words of the same name in the examples remain unchanged. Parameterized wrappers, dynamic names, and conflicting meanings are not inferred.

The curly brace form in ordinary source code balances the nested curly braces according to the original characters. Backslashes in the code will not escape curly braces, and percent signs will not start comments. Character forms support Unicode, `%`, and `#` delimiters; both forms allow crossing lines and support UTF-16 positions, CRLF, and incremental editing. When a closing delimiter has not been entered, subsequent content remains verbatim text until the boundary is filled.

Macro parameters and macro definition texts with known parameter syntax in the current source file will pre-read code tokens; at this time, curly braces are paired according to ordinary TeX rules, backslashes protect control characters, percent signs start comments, and nested grouping protects delimiters of the same name. Supports stable replication macros and pure static forwarding. When the outer known parameters or definition text are not closed, they are still read according to the pretokenization rules, and the diagnostics of missing outer right brackets is retained to prevent the escaped right brackets in the code from closing the outer grouping in advance. Comments before the code also continue normally; ordinary scope, zero-parameter packaging and unknown parameter syntax continue to use ordinary source code rules.

The blanks and TeX comments before the optional settings and language parameters are read according to the ordinary parameter rules; after the language parameters in the ordinary source code, the rules have been switched to verbatim reading, and `%` is the code delimiter. Signature help override settings and language names; LaTeX command prompts are not provided inside the code. After an existing local command is redefined, normal parameter rules will be restored after parsing. Do not expand LaTeX content executed by custom minted commands or infer options such as `escapeinside`.

The `minted` environment is read according to FancyVerb's line-by-line rules. Normal TeX options and language parameters are read before scanning the code from the next line; `\end{minted}` in the header parameters does not end the environment. Only the first literal `\end{…}` is checked for each line, and the name must be exactly `minted`; if another name appears first, subsequent tokens on the line are still code. The remainder of the true end line does not go into symbol, file dependency, or rename indexes; extra content errors reported by native tools on this remain as compile diagnostics. Folding and environment name linked editing use the real end boundary, and unclosed code can complete the end line. Supports CRLF, UTF-16 positional and incremental editing. Static analysis does not call Pygments or enable shell escape.

`\begin{minted}[options]{language}` also provides header signature help, covering unfinished options and language groupings. Options end at the first unprotected `]`, skipping ordinary TeX comments and continuation lines when reading the language. No prompts are displayed for header comments, the content after completing the language parameters, the code body, and the end of the closing line. The built-in signature will not be applied when `begin` / `minted` is redefined or undefined in the current project; definitions of the same name in other projects will not affect the current document, and unsaved setting changes will immediately update the prompt.

`\inputminted[options]{language}{file}` provides path completion, file linking, definition jumps, signature help, and versioned file and directory renaming. File names can use any suffix or no suffix; search according to the main documentation and TeX's `.tex` precedence rule. LaTeX examples in files are read as build data without adding tags, commands, or nested inputs to the source index of the main document; the same file is read simultaneously by `\input` and retains its source code usage.

Completion and file movement preserves filenames with spaces within curly braces, Unicode names use `\detokenize{filename}` without quotes, and existing wrappers remain unchanged. minted's default highlighting mode passes the file name directly to Python, and double quotes cannot be used as path wrappers; static editing skips such quoted parameters. Options, language, peripheral comments, and line breaks are preserved. Static files enter content snapshots before they are first compiled, and changes in file content, aliases, or paths can invalidate build results, old PDFs, and SyncTeX.

The explicit `verbatim` package option will bypass Python and use TeX to read the file directly. At this time, the static path only supports names without spaces. It is not recommended to complete the path with spaces. File movement will also refuse to introduce spaces. The same conservative limits apply to the legacy `draft` setting. Unicode names are still protected with `\detokenize`.

Path inference supports default search and common literal format options, including `linenos`, `breaklines`, `firstline`, and `lastline`; check the `\setminted` and FancyVerb settings within the project. Dynamic language or filenames, unknown/macro value options, `escapeinside` / `texcomments` / `mathescape` executing TeX, command redefinitions and import path prefixes skip static inference. `mathescape=false` and `texcomments=false` can continue to be used.

When the compiler explicitly reports a missing file, native errors for minted v3 and FancyVerb errors for `verbatim` mode locate the filename, use the `missing-minted-input` diagnostic code and provide bounded spelling fixes. Fixed rechecking source code, project settings, file search and document version, retaining language and options. Other Pygments, style, or shell escape errors retain original compile diagnostics.

```sh
cargo test --locked --test minted
cargo test --locked --test minted_environments
cargo test --locked --test minted_inputs --test missing_minted_inputs
cargo test --locked --test protocol minted_inline_
cargo test --locked --test protocol static_code_
```

After installing pdfLaTeX and minted v3, you can run the following command. The inline boundary uses the `verbatim` mode with shell escape turned off, and the pretokenization code also requires XeLaTeX; the file name, environment boundary, and dual-mode missing file repair regressions also require `latexminted` on the PATH. Highlight regression uses restricted shell escape and `highlightmode=immediate` to check the actual generated code content, check spaces and Unicode paths, and avoid the placeholder output masking problem of the first quick build. Environment regression checks both legal code and native errors with redundant content at the end of the line, and checks the real output before and after the tag is renamed:

```sh
cargo test --locked --test minted --test minted_environments --test minted_inputs --test missing_minted_inputs -- --include-ignored
```
