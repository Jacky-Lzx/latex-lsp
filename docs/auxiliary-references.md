# External documents and compiled reference information

`\externaldocument[prefix]{document}` of `xr` / `xr-hyper` will read tags in external `.aux` and support prefix completion, reference diagnostics, hover, source code jump and reference search within the project. When the external source file exists, jump to the corresponding label; when there are only auxiliary files, the number can still be completed and displayed. External documents will not be added to the source code dependency graph of the current project, nor will the macro declarations in them be introduced into the current scope; external labels cannot be renamed directly through the current project.

The local `.aux` is first read from the actual compilation output directory and the product path corresponding to `jobName`. If not found, the auxiliary file next to the main document is searched. Supports numbering, page numbers, and optional titles for `\newlabel`, and auxiliary file recursion for `\@input`; no TeX commands are executed. Hover to display existing source code information and these compilation values.

`textDocument/inlayHint` can display compiled numbers next to `\label{key}` declarations, numbers and page numbers next to label references and compiled flat literature labels next to literature citations:

```json
{ "latex": { "inlayHints": { "enabled": true, "numbers": true, "pages": false, "citations": true } } }
```

Page-number hints are disabled by default. Set `inlayHints.pages` to `true` to include page numbers next to references.

`\label{sec:math}` displays `→ 2` when its compiled number is 2. Declaration hints follow `numbers` and `enabled`, omit page numbers, and use the same hint style as references. Labels without a compiled number receive no hint.

Tip: Only declarations and references within the requested range are returned, up to a maximum of 1024 items at a time. Clients that support the corresponding refresh capabilities will receive the `workspace/inlayHint/refresh` request after compilation is completed. After the auxiliary file is modified, the cache is updated according to the file metadata.

For example, `\bibcite{paper}{7}` of the root auxiliary file will display `→ 7` next to the key of `\cite{paper}`, and `→ Doe26` will be displayed next to the key of `\bibcite{paper}{Doe26}`. `citations` is enabled by default and can be disabled independently of the tag `numbers`/`pages`. Only the current root and its `@input` document records are read, and external `externaldocument` documents are not imported. `nocite`, document data query and classification assignment do not display document tags; static naming and purely forwarded output citations follow the same rules.

Flat labels can have up to 256 characters, do not expand TeX, and do not display labels containing TeX syntax, control characters, or groups; skip conflicting records for the same key. natbib's numeric and author-year patterns can write out the same structured `bibcite` record, which currently does not guess the display format from its first field. biblatex's numerical hint reads the actual third field partition of `\abx@aux@number` and `\abx@aux@defaultrefcontext`, without using the reference counter of the first field in place of the partition. The first version supports projects with explicit `style`/`citestyle` as `numeric`, `numeric-comp`, and `numeric-verb`; real compilation records are required, and the common `defernumbers=true` will generate these records. No numbers are guessed from database order when there are no records.

The same physical reference must have the same number in all execution partitions of duplicate entries or shared roots. Author years, uncertified style or package options, custom document formats, uncertified context assignments, dynamic partitions, and incomplete auxiliary files are all skipped for numeric prompts; label prompts are kept independently. Backend projects will not fall back to the old `bibcite`. Digital metadata retains 4096 numbers/contexts per file, with a maximum of 8192 entries across files; AUX full read maximum 16 MiB, analysis effort budget is 32 MiB.

Prompts share project parameter semantics with edit-time reference diagnostics: redefined reference commands, macro parameter data, declaration bodies, literal contents, and token operands are skipped; references in normal text-style parameters are still prompted. Participation checks for unsaved definitions across files, skipping prompts when analysis is incomplete or over budget.

Named references such as static `\csuse{ref}{key}` and `\csname ref\endcsname{key}` also display numbers after the actual key parameters. When an interface or target command is redefined, the corresponding prompt is updated with the current project semantics.

These values come from existing auxiliary files and may be out of date after editing or compilation failure. Expired local auxiliary tags will not mask static warnings for deleted declarations in the source code. Read up to 2 MiB per file, retain 4096 tags and citation keys each, recurse up to 16 files per root auxiliary file, aggregate up to 8192 items each; ignore cleveref's internal `@cref` metadata. Dynamic file names, label declarations generated by macros, and code in any auxiliary files are not expanded.

It is known that the handwriting `\bibitem` in the biblatex project does not provide its background citation label even if `\bibcite` is written; these legacy records are not used for biblatex citation hints.

When `defernumbers` is not enabled in the normal number style, prompts for authentication numbers from the real loaded BBL literature list, supporting `defernumbers=false` and its default value; this mode ignores old AUX number records. When deferred is enabled, the numbering only takes AUX and does not fall back to the list order; the prefix can be completed through the BBL field of the same context. Both modes inherit the same partitioning, shared input consistency, request scope, and settings checks.

Non-deferred BBL numbers support signature format 3.3, a unique standard entry list for each partition; the number is returned only after complete reading. Collections, abbreviations, entry options, aliases, verbatim data, multiple lists, prefixes, and unknown/corrupted records are not currently authenticated in this mode. Reads up to 2 MiB, retaining up to 4096 entries and partitions; there is no fallback to legacy `bibcite` at this time, and independent label hints remain available.

Local `refcontext` supports the direct native `begin/end` environment and `refcontext`/`newrefcontext`/`endrefcontext`. The options are limited to pure literal `labelprefix` and `sorting`, and require global `defernumbers=true`. References take the default context recorded by AUX for each key; entering the print context alone will not directly select the label referenced there. Therefore, references to the same key in both printing contexts A and B may display `B1` instead of A1 and B1 respectively.

The non-empty prefix connects the `labelprefix` field of the same partition/context/key of the BBL through the real partition, default context and number of AUX. Hashing in context is only used for joins, no prefixes are deduced, and numbers are not guessed from list order. The prefix path allows a complete list of criteria for multiple different contexts; duplicate contexts, duplicate entries, missing fields, TeX formats, collections, and unknown records revoke the entire prefix certification, and individual empty prefix AUX tags and tag references remain. Maximum 4096 list and total entries, 2 MiB BBL; maximum 256 characters each for prefix and final label.

Naming context declarations, unauthenticated auto-allocation, `localrefcontext`, dynamic options, forwarding/naming context calls, redefinitions, hooks and custom formats continue to skip numeric prompts.

```sh
cargo test --locked --lib bib_context_tests:: -- --include-ignored
cargo test --locked --test protocol local_context_citation_hints_
```

Direct and unredefined strong allocation `\assignrefcontextentries[options]{keys}` supports deferred numeric hints for ordinary resources, with options limited to literals `sorting` and `labelprefix`. When `sorting` is omitted, the biblatex package options are required to explicitly give the literal ordering; the style's ordering default is not inferred. The automatic allocation of categories is also certified according to the following membership rules; the automatic allocation of keywords is also certified according to the following BBL members; source code collections and IDS intersect to continue protection.

The asterisk weak allocation `\assignrefcontextentries*[options]{keys}` also supports the same literal options and compilation records. Strong allocation takes precedence over weak allocation, and they check wildcards first and then single keys; similar allocations are updated according to the last execution. Weak allocation only takes effect outside the explicit context; when entering the explicit context, weak allocation is skipped and the AUX default record is used, without directly adopting the prefix of the environment. Direct native `refcontext` environment and `refcontext/newrefcontext/endrefcontext` commands authenticate local switches according to actual grouping: curly braces, normal environment and native `begingroup/endgroup`, `bgroup/egroup` are restored to the state before entry at the end; the entry allocation itself is still globally saved. Group and context boundaries can span input files, and the filename argument does not create groups that wrap around the input execution. Unknown/mismatched scopes, named/forwarded grouping controls, implicit grouping in the macro body, or math switches continue to skip weak hints. Ordinary formulas can appear before and after contextual commands; context switching within dollar and bracket math is not yet certified. Direct and unredefined `endinput` only executes the current line, and subsequently ignored parentheses do not affect the grouping of the calling file; named/forwarded termination calls continue to be protected. Scope depth up to 128, inherits 32 MiB analysis budget.

Static `assignrefcontextcats[options]{categories}` and its asterisk form also support deferred numeric hints, including static named calls and pure forward declarations that have been performed in the preamble. The options follow the literal `sorting`/`labelprefix` certification assigned to the entry. The assigned value of each category is saved in numerical partitions, and the iteration order of the categories is saved globally; assigning the category with the same name again will move it to the end. Each reference takes the valid allocation of the last matching category. Strong allocations in the same category take precedence over weak allocations, and different categories are still covered in order. Item allocation is applied last, so item weak allocation can also override category strong allocation. The category name `*` is a literal name, not an entry wildcard.

The member must be created by `DeclareBibliographyCategory`/`addtocategory` that can be confirmed in the current source code, and must be consistent with all classification members in the selected output directory, jobName, and recursive AUX. Classification members are global collections and are natively preloaded from AUX before the text, so members added later can also affect earlier references. Unsaved member changes before AUX updates, potential updates in macro bodies/callbacks/captures/unknown parameters, redefinitions, database generated code, source code collections and uncertified IDS all continue to skip related prompts. Missing, malformed, or mismatched classification records do not borrow default numbers; they do not affect independent entry assignment prompts. Keywords are automatically assigned as follows independently certified by BBL members.

```sh
cargo test --locked --lib automatic_categories_
cargo test --locked --lib native_automatic_category_hints_ -- --ignored --test-threads=1
cargo test --locked --test protocol automatic_category_hints_
```

Static `assignrefcontextkeyws[options]{keywords}` and its asterisk form support deferred numeric hints for ordinary resources, including static named calls and pure forwarding that has been performed in the preamble. Keyword members only take the `keyw` record of the fully authenticated BBL, and accumulate members of all loading contexts by numerical partition; the original database fields are not directly inferred, so the strings and XDATA processed by Biber continue to use the real output. Keywords use an independent global append order and partition-by-partition strong/weak mapping, applying keywords first, then categories, and finally item assignments; weak assignments are still skipped within explicit contexts.

Keyword authentication is limited to literal lists without expansion or nested grouping, supporting ASCII, Unicode letters/digits, and basic combined accents (U+0300–U+036F), including Chinese and Greek. The original spelling, capitalization and combination form of the source code and the actual BBL are retained, and NFC normalization is not automatically performed; for example, when Biber outputs members as `café`, the source code decomposition form `café` will not hit the same allocation. pdfLaTeX, XeLaTeX, and LuaLaTeX all use this literal identity rule.

Internal ordinary spaces, tabs and line breaks are normalized according to TeX, comments remove the remaining content of the current line and line breaks; spaces before items are ignored, spaces at the end are retained, and `*` is a literal keyword. An empty list does not change the allocation. The allocation itself does not load entries and does not generate prompts. Unknown code, paragraphs generated by blank lines, Unicode whitespace/control characters and uncertified symbols, uncertified source code collections/IDS and incomplete BBL continue to omit relevant prompts. The expansion of keyword indexing continues to use the 32 MiB upper limit; complex keyword data or index exceeding the limit will not affect the certified numbers in the independent entry allocation.

```sh
cargo test --locked --lib bib_context_tests::keywords::
cargo test --locked --lib native_automatic_keywords_ -- --ignored --test-threads=1
cargo test --locked --test protocol automatic_keyword_hints_
```

The assignment of entries updates the global state of each number partition in the actual execution order, and the end of the TeX curly brace grouping does not undo it; the same key can display different labels before and after assignment. Wildcard `*` takes precedence over single key assignment, and an empty list does not change the state. The native list ignores the blank before the item, but keeps the trailing blank; `a ` or `* ` will not be regarded as the static key `a` or wildcard `*`, and the category name is the same. Prompts are only displayed after the actual output reference, the assign command itself does not load entries and does not generate prompts. Duplicate entry and shared root documents still require all executions of the same physical reference to obtain the same complete label.

The assigned reference uses the complete AUX `(section, key, context)` number, combined with strictly loaded BBL sorting and real prefix authentication; when the corresponding record is missing or conflicting, the prompt is omitted and the default context number is not borrowed. Unwritten `labelprefix` and explicit `labelprefix={}` authenticate native empty context components and empty string digests respectively; the latter allows Biber to omit empty prefix fields, and other unknown digests still require real fields. This explicit analysis does not relax the authentication boundaries for source collections or full renames.

```sh
cargo test --locked --lib bib_context_tests:: -- --include-ignored
cargo test --locked --test protocol context_assignment_hints_
```

Static `csuse`/`csname` entry allocation and zero-parameter pure forwarding commands support the same strong and weak numeric prompts. Forwarding declarations must be actually executed in the global preface by unredefined native declaration commands; cross-preface input and up to 64 executed forwarding edges are supported, and outer declarations can be earlier than inner declarations. Copies of commands within groups, within document bodies, deferred execution, conditional offers, and captures continue to be protected; named/forwarded contexts and group controls are still not authenticated. Unsaved changes to provision files, shared roots, and build records are prompted for rechecking.
