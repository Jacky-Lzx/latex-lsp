# Static named references

[Back to documentation](README.md) · [Label](labels.md) · [Document](bibliography.md)

The actual keys called by `\csuse{ref}{key}`, `\csname ref\endcsname{key}` and corresponding documents support jump, hover, reference search, document highlighting, preparation for renaming and cross-file renaming. Reference lists, ranges, optional descriptions, and structured biblatex parameters follow the key boundaries of the direct call; command name groupings and description text are not part of the reference key. Tags and document names are parsed separately.

Zero-argument pure forwarding user commands and alias chains use the same key semantics. For example:

```tex
\def\myref{\ref}
\newcommand{\mycite}{\cite}
\myref{intro}
\csuse{mycite}{paper}
```

These calls support undefined key diagnostics, existing build number hints, and the navigation, renaming, and completion mentioned above. The `myref` / `mycite` control words in the call still navigate to the user macro declaration, and the key parameters use the syntax of the final citation/documentation command. Wrapping macros with parameters, multi-token replacement text, expansion definitions, and copy commands are not inferred as pure forwarding; when the alias is ambiguous, forms a cycle, or the final built-in command is rewritten, the reference meaning is not guessed. Potential calls of the macro body can participate in safe renaming, and actual diagnostics still excludes uncalled declarations and parameter data.

Contextual completion is also provided for actual key parameters. The entered key prefix is replaced with the remaining suffix, preserving other list members, optional descriptions, and subsequent parameters; supports unfinished grouping, UTF-16, and CRLF. Completion follows the label/document candidate and parameter parsing of direct calls, and does not provide reference key candidates in command name parameters, description text, dynamic names, and parameter data. Shared origins are only completed when the same call and key position can be confirmed in all consumers, and the results of related unsaved redefinitions are immediately updated.

For example:

```tex
\label{intro}
\newcommand{\later}{\csuse{ref}{intro}}
\csname ref\endcsname{intro}
```

Renaming `intro` will also update the declaration, the static references in the macro body, and the keys on the last line. Fully declared replacement text can participate in static editing, and diagnostics do not predict which warnings will be generated by unexpanded macro text. Dynamic names, arbitrary macro expansion, and the capture meaning of copy commands are outside the scope of this feature.

The index compares each root document's interpretation of the shared source. When the named interface or target command is explicitly redefined, the relevant parameters are processed as ordinary user commands; when the meanings of different consumers are inconsistent, or the potential reference is located in the parameter data/token operand that cannot be confirmed, the renaming of the relevant key is rejected. Confirmed verbatim and literal examples remain in the original text. Definition and redefinition of independent projects with the same name do not affect each other.

Edits use existing document versions and project share scope validation. A single analysis covers interrelated projects and is limited to a cumulative 32 MiB of source code, 200,000 commands, 8,192 statements, 20,000 keys per source, and a cumulative 100,000 key explanations; partial rename editing is not returned when the project index is incomplete or exceeds budget.

Unique, well-ordered, and reliably sourced local copies can define common parameter boundaries. For example, in `\let\strong\textbf\strong{Text}\ref{intro}`, the following `ref` remains editable. This parameter shape inference does not authenticate copies as built-in reference aliases; arguments to copy user macros are still treated as data, and copies of unknown, duplicate, or later source declarations continue to retain conservative protection.

Capturing a reference copy may still read keys such as `\let\saved\ref\saved{intro}`. Key indexes record potential calls along static copy and pure forwarding chains, distinguishing tag/citation keys, lists, ranges, and description parameters according to the original command syntax; rejecting only updated partial renames declared when relevant potential keys exist. Supports named calls and cross-file unsaved declarations, and the original command will not be unprotected if it is subsequently redefined. Copies without calls, confirmed literal instances, keys with the same name in another namespace, and standalone items remain editable; unknown capture meanings are not therefore certified as navigation targets. A maximum of 100,000 nodes/edges can be checked in the copied graph, and some renames will be rejected when the limit is exceeded.

For undefined diagnostics, spelling fixes and numbering tips for named references, see [Static Diagnostics](static-diagnostics.md) and [Auxiliary File Reference](auxiliary-references.md).
