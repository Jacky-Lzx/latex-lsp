## Analysis scope and source confirmation

- Compilation result analysis: errors, LaTeX/package/document class/font warnings, missing words, engine warnings, Overfull/Underfull prompts, and BibTeX/Biber documentation errors and warnings, locating subfiles, documentation entries, and line numbers; the results provide PDF, log path, and output summary. Only use latexmk's last pass of TeX logs to avoid retaining resolved reference warnings.

Compilation warnings for undefined tags or documents will try to indicate specific key names, including single keys in lists, multiple references on the same line, and package warnings using single quotes; entire line positions will be preserved when an unambiguous match cannot be obtained from the source code. The log file context supports sources such as `.def`, `.clo`, paths with spaces/brackets, and long filenames with TeX word wrapping.

`Info` messages for standard LaTeX, packages, document classes, fonts, and encodings are only log messages and do not generate errors or warnings. File names and left and right brackets in the text and confirmed continuation lines will not change the diagnostic source; 60 / 79 column wraps, `MessageBreak` and longer continuous messages are supported. Incomplete messages still retain the actual file entry and exit events; adjacent information messages do not spell out warning or error text.

Even if the message text with a clear continuation line prefix contains "file name: line number: error", warning example, source code echo, `<…` resource text or PDF output record, it will still be processed as the message text and no additional diagnostics will be generated. Subsequent real file switching, error locations, and log omission boundaries continue to be parsed independently.

When explicit "file name: line number: error" spans lines, the actual file path and line number are restored, including the case where the file extension or line number separator happens to be split; traditional `!` error and explicit position error messages also support byte wrapping, retaining the splicing and original spaces within the word. Recovery does not cross omitted boundaries between adjacent diagnostics, file switches, TeX source contexts, or large logs.

When the first half of the wrapped file name of a traditional bracketed log happens to be another existing file name, continue to check whether the subsequent content forms a longer actual source to avoid assigning errors or warnings in long files to files with the same prefix. Compatible with brackets, Chinese, and with or without short file prefix; when the long source disappears, it remains unconfirmed and does not switch to short prefix files. Fully quoted filenames are still treated on quote boundaries.

When missing input files or packages cause `Emergency stop`, the original error containing the missing file name is retained; it is compatible with traditional and explicit file line number logs, and retains subfile ownership and the project macro context when the error occurred. Only consecutive file search prompts from the same source can be associated with the end position; when file switching, other diagnostics, log truncation, or beyond the search range, the original error is retained and the conservative first line position of the file is used.

Undefined control sequence errors will use TeX's `l.N` source code context to accurately mark the directly called command; multiple errors on the same line are kept separately, using UTF-16 positions. The context that omits an excessively long prefix must uniquely match the complete command; the entire line of diagnostics is retained when the macro expands the stack, the source code does not match, or the context is incomplete.

Math mode and direct undefined commands in the box also support precise diagnostics and spelling repair. When TeX additionally outputs a single `<recently read>` command, it will simultaneously check the literal command, the following line number, the source code prefix, and the current source; other expanded frames, repeated omitted context, or unmatched commands will continue to roll back the entire line to avoid attributing internal macro errors to valid calls.

For commands, environments, counters, and missing input file errors with file names and line numbers, the source code context is only used when the source file reported in the log can be parsed into an actual file. When the source path does not exist or is actually a directory, the error is still displayed in the main file, and the entire line position is retained to avoid borrowing text with the same name in the main file to generate accurate repairs.

When the subfile entered by the traditional bracketed log has disappeared, is not an actual file, or the path cannot be resolved, the source unconfirmed status will also be retained. Errors, quotes, and box warnings do not borrow the source scope, spelling candidates, or inclusion relationships of the parent file; nested resolvable sources and exited parent files continue to be positioned normally.

The same source check is used for tags with filenames and line numbers, citation keys, PDF targets, missing chapters, and boxes. Warning: When the source cannot be confirmed, the original message and full line position are preserved, names or cross-line ranges from the main file are not borrowed, and corresponding spelling edits are not provided. Warnings such as PDF engine, box, and missing words will continue to be counted as warnings even when using this file line number format.

When midsections of compilation output or logs are omitted, legacy errors and warnings remain in "source unconfirmed" status until a resolvable source is re-observed, are displayed in a valid full line range, and do not borrow the main file name to generate an exact fix. Diagnostics with clear file names and line numbers can still independently confirm the source; normal positioning can be restored after entering a parsable subfile or main file.

When the log reports line 0 or a line number outside the file range, the diagnostic retains the original line number data and displays it using the valid full line position in the file; text with the same name sandwiched into the first or last line is not considered a precise position and does not provide repair or repositioning of the PDF target accordingly. Normal PDF output warnings for missing line numbers are still positioned according to the actual input for that compilation. Diagnostics with different location data will be released separately to avoid the same messages covering each other.

For macro errors, undefined counter errors, and missing file errors for ordinary input, pictures, code lists, and verbatim input, the shortened source code echo must correspond to a unique position in the entire line of source code; when the same suffix also appears in other calls or verbatim content, the entire line of errors is retained, and spelling repairs that may correct the wrong call are not provided. A full echo or a unique shortened echo can still distinguish duplicate names.

`.aux`, `.bbl`, `.toc`, `.lof`, `.lot`, `.out`, `.nav`, `.snm` and `.vrb` Compilation errors or warnings in are located in the actual generated files, supporting traditional errors, explicit file line numbers, spaces/Chinese paths, and long path wraps; these files still do not enter the project source index. If the file is rewritten after LaTeX reports an error, causing the original line number to no longer exist, the diagnostics remains in a valid position and the original line number is retained in the message and `data.reportedLine`.

## Commands, environments and counters

- Accurate diagnostics and path fixes for missing input files, packages and document classes will check macro argument boundaries and skip `input` and package/class load commands that are ungrouped arguments to other macros. Supports project macro signature and source re-verification; retains line-level diagnostics when commands are redefined or parameter boundaries cannot be confirmed to avoid modifying unexecuted file names in macro calls.

`LaTeX Error: Environment ... undefined.` can also accurately mark the environment name of `begin`, recognize standard LaTeX help prompts, newline separated commands and arguments, and multiple calls on the same line. The truncation context must uniquely match the complete argument; dynamic names, macro expansions, ignored regions, and source code mismatches retain entire line positions. Accurate diagnostics come with `undefined-environment` code and environment name data. `begin` / `end` preserves line-level position when used as ungrouped arguments to macros, unidentified redefinitions and dynamic sources also do not provide an exact fix. Environment diagnostics records the source of the macro when the error occurs, and rechecks the macro parameters and pairing boundaries before repairing; when matching the end tag, the environment control sequence consumed by the macro is skipped. Names in the truncation log must match uniquely in source lines to avoid modifying text with the same name in unexecuted branches.

`LaTeX Error: No counter '...' defined.` can precisely identify static counter names in `setcounter`, `addtocounter`, etoolbox's `defcounter`, `stepcounter`, `refstepcounter`, and `usecounter`, preserving numeric expressions. Traditional quotes, multiline arguments, and multiple calls on one line are supported. Macro expansion, dynamic or incomplete arguments, and ambiguous log context retain line-level locations; precise diagnostics include the `undefined-counter` code and counter name data. A counter command consumed as an ungrouped macro argument is not a direct call. Traditional macros, TeX macros, xparse arguments, and static aliases are checked against project macro signatures loaded before the error; uncertain dynamic sources or redefinitions retain line-level diagnostics. Precise diagnostics record macro sources and revalidate those sources and the complete call before offering spelling fixes. Suspended parent files only exclude uncertain declarations; counter candidates still come from the current project.

etoolbox's `ifltxcounter` checks whether the counter exists, does not generate undefined counter errors, and is not a candidate for location or spelling repair of such errors; when checking and assignment occur in the same line, the repair only modifies the assignment parameter confirmed by the log. For operation examples, see [Counters and Theorems](counters.md).

The shared/reset number parameters of parent counters, counter aliases, and theorems also use exact counter diagnostics, including the two name parameters `newcounter`, `newaliascnt`, `newtheorem`, and `counterwithin` / `counterwithout` / `numberwithin`; asterisks and optional format parameters are recognized. The repair only changes the name of the log confirmation, retaining the declaration name, title, format and parameter separator; it is not recommended to form a self-alias or self-number reset relationship. Optional counter parameters are read according to TeX's square bracket ending rules; parent counters, theorem sharing and reset counters containing the literal `[` participate in navigation, completion and renaming. When a name containing `]` is introduced, the parent counter and shared parameters are supplemented with curly brace protection as needed, and the theorem reset parameter uses the static `\detokenize{name}`, so that consecutive renames retain the counter relationship and numbering format. The entire line of diagnostics is retained when two arguments have the same name, have dynamic names, or incomplete calls cannot confirm the specific location.

When `begin` is closed by a different name `end`, compile diagnostics pinpoint the current closing name with the actual name and expected environment as `mismatched-environment-end` code; identify LaTeX messages with starting line numbers. Multiple closing errors on the same line are retained individually, and the entire line position is retained when the macro is expanded or the context is uncertain.

Precise diagnostics of environment mismatch provides a quick fix of "closing the expected environment", modifying only the current `end` name. The expected environment in the log must be consistent with the static nested stack of the same document; this fix is not provided for collateral errors caused by undefined environments, dynamic stacks, previous cross closures, ignored regions, and expired requests.

Pinpointed undefined commands also provide up to 5 spelling suggestions, derived commands from built-in commands, custom macros of the current project, registers, and environment/counters/boolean switches. For example, `\\sectoin{Intro}` can be repaired to `\\section{Intro}`, retaining the original actual parameters. It is recommended that manual selection is required; no repair will be provided when there is a declaration with the same name, the candidate is ambiguous, the macro expansion is wrong, the source code context cannot be confirmed, or the diagnostics has expired.

Undefined commands reported by the compiler for key parameters `\ref`, `\pageref`, `\eqref`, `\cite` and `\nocite` that contain only one control word (e.g. `\ref{\keynme}`) are also pinpointed and provide macro name spelling fixes. Also supports hyperref's `Ref`, `autoref`, `autopageref`, `nameref` and square bracket tag form `hyperref`, varioref's `vref` / `Vref`, natbib case citation, author, year, and alias citation commands, and `bibentry`. `hyperref` Tags can have an extra layer of curly braces, fix retaining square brackets, curly braces and link text. The internal prefix errors of `subref`, `vpageref`, `getrefnumber`, `getpagerefnumber` and `refused` can also be located to the macro name in the key parameter; only compile error frames matching this interface are accepted, the repair retains the asterisk, description parameter and the original key expression, and does not infer the expanded tag value. Supported asterisks, optional descriptions, and parameter brackets are retained, and macro-expanded tags or citation keys are not inferred; mixed key lists, indirect expansions, parameters with semantic gaps, and unconfirmed source code echoes are retained as common errors. Ordinary macro calls actually indexed in the dynamic key parameters support definition jump, hover, quote, highlight and versioned renaming; the macro name remains independent from the static label and citation key of the same name, and the comments and verbatim text in the parameters are not involved in the name change.

The pinpointed undefined environment provides spelling suggestions for built-in environments and custom environments for the current project, such as changing `algin` to `align`. One operation simultaneously modifies the current `begin` and the corresponding `end` in the same document, retaining the nested environment, other calls with the same name, blanks and text. No suggestions are provided when pairings are missing, cross-closing, dynamic nested, or candidate definitions are ambiguous; versioned editing and old client operations are supported, and version, candidate, and pairing relationships are rechecked before application.

The pinpointed undefined counter provides spelling suggestions for the built-in counter, the current project's `newcounter` / `newaliascnt`, and theorem that owns the counter, such as changing the name of `setcounter{equatoin}{2}` to `equation`, preserving numeric values, whitespace outside arguments, and other calls. Whitespace within counter names is semantic and whitespace removal is not matched; such diagnostics preserve full line positions. Unnumbered or shared numbered theorems are not candidates for independent counters; repairs are refused when there is already a declaration with the same name, the candidate definition is ambiguous, the diagnostics is expired, or the current actual parameters no longer match, and is compatible with old clients.

When the name parameter of a single-name interface contains only a common macro, such as `\csuse{\keyname}`, the undefined macro reported by the compiler pinpoints and provides versioned spelling fixes; applies to single-name declaration, read, modify, and conditional detection interfaces. The same applies to single naked control word parameters such as `\csuse\keyname`. The repair retains the naked writing method and subsequent actual parameters and text. `cslet` Also checks read source commands; mixed names and user macro wrapping continue to preserve full line diagnostics.

The two name parameters of `ifcsequal` and `ifcsstrequal`, as well as the source names of `csletcs` and `letcs`, also support the above diagnostics and repair. It is required that only one name parameter is a direct macro, and the remaining name parameters are static literal values; check the source code echo of the complete call, and retain the copy target and conditional branch. Target control words for `letcs` are not mistaken for name expansion errors; multiple dynamic names, duplicate macro parameters, and complex expansions of `csletcs` target names continue to use full line diagnostics.

## Color and color model

- Compiled xcolor `Undefined color` bug to target confirmed static names and provide spelling fixes from the current project's color definitions and built-in colors. Supports common color selections, boxes, pages, aliases, masks, and color extraction/conversion calls, fixes to preserve blending ratios, inverse color symbols, text, comments, and CRLF, and rejects expired edits. Line-level diagnostics are retained for incomplete or non-unique source code echoes, duplicate names in a single call, macro expansion, and delayed color mixing settings.

- Pinpointing and spelling fixes are also supported for static model names such as `rbg` → `rgb`, `HTLM` → `HTML`, `gary` → `gray` when xcolor explicitly reports `Undefined color model`. Supports color declarations and model parameters of common text, pages, and boxes, including the independent background model of `fcolorbox`; editing retains color values and text. Row-level diagnostics are retained when the model or component contains macros, multiple models have the same name in the same call, the command is redefined, or the source code echo is unclear.

- Color diagnostic multiplexing macro signatures identify ungrouped control sequence arguments to avoid misjudgment of color commands passed as parameters as direct calls. Support for legacy declarations, delimiter-less TeX macros, and xparse optionals, flags, and delimited arguments; normal completed calls, font switching, and color extraction/conversion output parameters retain precise fixes. Preserve row-level diagnostics when preceding macro parameter boundaries cannot be confirmed; this analysis does not perform macro expansion.

## References and repeated declarations

biblatex's multi-set citations and volume number citations check the overall description, each set of parameters and the position the compiler reads forward, locate missing literature warnings to the actual key names, and provide spelling fixes. Volume and page numbers are not restored as citation keys; see [biblatex Citation Guide](biblatex.md) for supported command and parameter rules.

For undefined references that can be precisely located, quick fixes will provide up to 5 similar key names from known tags or documents in the current project, supporting adjacent character reversal and Chinese. It is recommended to manually select and only modify the current reference; skip duplicate definitions, macro-generated key names and existing keys, and the diagnostics will become invalid after expiration.

TeX may still generate the PDF and return success when the `\include` chapter is missing. The server will convert `No file chapter.tex.` to `missing-include` warning, identify and mark the static chapter path in the calling file; support automatic wrapping of long paths, fill in the file and clear it after recompiling. Missing `.aux` / `.bbl` messages during normal first compilation, and optional file messages that cannot be associated with chapter declarations will not be used as chapter warnings. UTF-8 characters in logs and compiled output that are separated by byte breaks by TeX will be restored first, and Chinese and other paths and diagnostic locations of corresponding files will be retained.

Duplicate tags reported by the compiler can locate at least two explicit declarations in the source code actually read by this build, and correlate the positions of other declarations. Keep the original auxiliary file warning when there is only one current declaration left to avoid incorrectly marking the normal label when the old `.aux` is still read in the first round after the fix; clear it when subsequent compilation logs no longer contain duplicate warnings.

The duplicate key of handwritten `\bibitem` can also be located from the compilation warning to the declaration in the actual input, with the diagnostic code `duplicate-bibitem`, and associated other entries; optional display labels, Unicode keys, and duplicates in the same file are supported. The LaTeX kernel uses the same duplicate warnings for ordinary tags and bibliographic entries, and retains auxiliary file locations if there is a duplication of current declarations in both categories; ordinary tags, BibTeX database entries, and uncompiled files do not serve as associated locations for bibliographic entries. Also avoid flagging old auxiliary file warnings to normal entries when only one entry remains after repair. `analysis.duplicateLabels` still logs kernel warnings for keys actually reported, including such literature entry keys.

Identification of unresolved references also checks against the standard `undefined` status after the end of the key name and the input line number. When the word appears in key names, page names or general descriptions, the defined tags or citations will not be marked as unresolved, and corresponding spelling repairs will not be provided; real undefined warnings, package continuation lines, and empty page numbers of `pagenumbering{gobble}` will still be analyzed and accurately positioned.

When the long reference key itself contains a complete warning ending and happens to span a log break, the subsequent content will continue to be checked to avoid cutting the actual missing long key into another healthy short reference. Complete keys enter compilation analysis; keys containing content that cannot be statically edited retain row-level positions, no error fixes are provided to healthy references, and independent files and error boundaries still maintain their original ownership.

## Typography, fonts and PDF targets

pdfTeX's `!pdfTeX error:` when outputting PDF will also show specific compile diagnostics, such as missing Type 1 font files; retain the full file name and error description in newlines, and omit the generic fatal exit prompt. If there is no source code line number, it will be positioned at the beginning of the main document to avoid guessing the font declaration position.

The general fatal exit prompt of engines such as LuaTeX will no longer be displayed repeatedly when there is a specific error, and the compilation result summary will show the actual cause first; when there is no more specific error in the log, the general exit error will still be retained.

When the PDF driver fails, fatal messages and related warnings for XeLaTeX's `xdvipdfmx` and standalone `dvipdfmx` are also shown as compile diagnostics, including errors that only write to stderr. Consecutive `>>` details in font warnings are merged, retaining the actual mapped font file name; the driver message is positioned at the beginning of the main document and does not borrow TeX subfiles or subsequent line numbers.

Overfull/Underfull diagnostics will cover the complete source code range specified by `at lines N--M` in the log, and mark `overfull-box` / `underfull-box` diagnostic codes respectively; UTF-16 and CRLF are supported, and the exception range will be limited to the document. For the number of categories and the maximum typesetting index in the construction results, see [Typesetting Warning Analysis](typesetting.md).

The engine's byte-wrapped box warning will restore the complete message, including split line numbers, numbers, and range delimiters; it is compatible with traditional logs and formats with file names and line numbers. Only merge the complete warning headers that can be confirmed, and do not combine the box content, adjacent diagnostics, file switching or log omitted fragments into the warning; when the source cannot be confirmed, the fallback position and the source unconfirmed mark will continue to be retained.

Font substitution, document class, and engine warnings, as well as the general `Missing character` missing font message, will appear as warnings even if the compilation succeeds and produces a PDF. When the engine outputs a missing word error in the form of `!` or "file:line number" under settings such as `\tracinglostchars=3`, the error level is retained and included in the number of build errors, and is not merged with the missing word warning at the same location.
