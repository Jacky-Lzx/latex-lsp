# biblatex entry sets

[Documentation](README.md) · [Documentation](bibliography.md) · [Collection Build diagnostics](bibliography-diagnostics.md#biber-bibliography-entry-sets)

`\defbibentryset{set key}{member keys}` declares a dynamic collection and supports completion of collection keys and member keys, definition jump, hover, reference search, highlighting, semantic token, selection range and cross-file renaming.

```tex
\addbibresource{refs.bib}
\defbibentryset{collected}{first,second}
\cite{collected}
```

The first parameter declares the collection key, and the second parameter references the document member. Renaming `collected` updates the collection declaration and references, retaining members; renaming `first` updates database entries, member lists, and other references. The namesake text in the label and body remains intact. Collection keys also appear in bibliography completion and documentation symbols.

Member parameters support comma lists, comments, newlines, and completion in incomplete input. The signature help distinguishes between `{set key}` and `{keys}`; two parameters are provided for command snippet completion. If there are already parameters, only the command name is completed. Collection names use a single static citation key rule, supporting Unicode and literal double quotes.

The declaration is created only when both parameters are complete and the collection name is static. The name, asterisk, and optional argument forms generated by the macro do not generate speculative declarations. Examples in comments and verbatim content are not indexed. Dynamic names within members are not expanded, and additional groupings and subsequent bodies are not referenced as members.

The collection shares the citation key namespace with database entries, handwritten documents, and the `ids` alias. Ambiguous renaming will be rejected for identical definitions or new name conflicts; project isolation, shared source checking, and versioned editing follow document editing rules. Only the preface fragments maintain the above notation editing rules. Ordinary complete projects and `refsection` projects with resource selection authenticate static collection identities according to numerical partitions and actual input order. For details, see [Partition Document Identity](bibliography.md). Different numerical partitions of the same resource list are not merged, and database entries may still be used when explicitly referencing and then defining the collection. Grouping does not return the collection definition to its pre-grouping state.

The database relation field completion of the partition project is based on all digital partition certification candidates, displays the actual effective source code collection or book information, and supports static named collections and unfinished input. Source code collections are only candidates for `crossref`/`xref` with existing database parent keys; source code collections without database entries, XDATA of active collections, default related clones, and nested entrysets do not provide candidates. TeX citation and set member completion, missing key diagnostics, full citations and renames share authentication across all consumers and numeric partitions. These interactions are supported when the unique static IDS is disjoint from the source code collection name and the primary key it belongs to; when the primary key is covered by the collection, it also supports navigation, hovering, full quotation, highlighting, alias self-renaming and missing key diagnostics; reference and legal relationship candidates share the same authentication, and indirect nested members do not provide candidates; the renaming of the primary key must simultaneously move the unique database primary key and verify all original library consumers. Dynamic or lazy definitions, conflicting declarations, nested collections, uncertified IDS, executable `@preamble`, and handwritten documentation remain protected. The index does not perform arbitrary macro expansion.

Unsaved edits immediately update the declaration and member index. After closing the buffer, the loaded project source restores the disk contents. See also [Collection Diagnostics](bibliography-diagnostics.md#biber-bibliography-entry-sets) for Biber's native warnings for static `@set` and member fields.

```sh
cargo test --locked --test biblatex_sets
cargo test --locked --test protocol bibliography_dynamic_sets_
cargo test --locked --test biblatex_sets -- --include-ignored
```

Real Biber test verifies the dynamic collection in the index through normal mode `.bcf`, comparing the complete `.bbl` after independently renaming the collection key and member key, including the new collection key and Unicode member key containing double quotes. This test only requires Biber; it does not run validations for LaTeX or alternative biblatex macro expansions.

Partitioned collection read-only identity regression covers normal/static named calls, members, preamble and grouping, numeric partitioning, first reference order, wildcard loading, unsaved input and shared consumers, Unicode/CRLF and parsing budgets. Native regression requires pdfLaTeX, biblatex and Biber. Check the actual entry types and navigation targets of BBL under ten execution orders:

```sh
cargo test --locked --test biblatex_source_sections
cargo test --locked --test biblatex_source_sections -- --include-ignored
cargo test --locked --test protocol source_set_navigation_
```

The source code collection navigation of database relational fields has also returned, covering five types of fields, digital partition conflicts, first request locking, UTF-16/CRLF, duplicate fields and unsaved consumers. The native test compares the two parent entries of collection and book and the actual inherited fields:
