# Counters and theorems

## Completion and signature help

Counter operations support command snippets, signature help and name completion, including `setcounter` / `addtocounter`, `stepcounter` / `refstepcounter`, `value` / `arabic` and other formatting commands, `counterwithin` / `counterwithout`/`numberwithin`. Name candidates come from built-in counters, `newcounter` / `newaliascnt` of the current project, and theorem statements that own counters; support new counters, aliases, and shared/reset parameters of theorems, retaining existing name suffixes, blanks, and other arguments. Candidates between different papers are isolated by dependency, and macro-generated names are not inferred.

## Navigation and renaming

Static `newcounter` / `newaliascnt` declaration supports jump, hover, references, document/workspace symbols and cross-file renaming. Rename linkage maintenance counter operations, sub-counter resets, theorem sharing numbers, aliases and formatting commands, including literals `csname`, `aliascntresetthe` and alias metadata; the display text of independent macros with the same name and cleveref remains unchanged. Reject changes in cases of name conflicts, shared references pointing to independent statements in other papers, or ambiguity over ownership of formatting commands for theorems and counters of the same name.

When renaming static `\newtheorem{claim}{Claim}`, synchronize maintenance of `\newtheorem{lemma}[claim]{Lemma}`, `\newtheorem{fact}{Fact}[claim]`, `\newcounter{inner}[claim]`, common counter operations with `counterwithin` / `counterwithout` / `numberwithin`, and Derived commands such as `\claim`, `\endclaim`, `\theclaim`; support literal `\csname theclaim\endcsname` and do not expand dynamic macros. Theorems with shared counters preserve the underlying counter, and unnumbered theorems do not modify independent counters. Changes are rejected when the new name conflicts with a counter or derived command, or the shared reference belongs to an independent counter in another project; when there is a direct derived command call, the new name must be able to form a TeX control sequence.

## etoolbox counter operation

The static counter names of `defcounter{counter}{expression}` and `ifltxcounter{counter}{then}{else}` support completion, jump, reference, renaming and semantic highlighting. Both commands provide fragment and signature help. The same rules apply to custom counters and theorems that have counters.

```tex
\usepackage{etoolbox}
\newcounter{exercise}
\defcounter{exercise}{2+3}
\ifltxcounter{exercise}{Exists}{Missing}
```

`defcounter` defaults to local assignment and supports the `\global` prefix. Renaming only maintains the counter name and related references, retaining expressions, branch bodies, independent macros with the same name, labels, comments, and verbatim content. Dynamic names generated by macros are not inferred; names containing semantic gaps are not merged with ordinary names, and explicit completion can replace the entire name with a candidate.

Compilation report `defcounter` supports precise positioning and spelling repair of names when undefined counters are used. `ifltxcounter` Execute the second branch for non-existent counters and do not use it as the source of undefined counter errors; when there are checks and assignments in the same line, the fix is to only modify the assignment parameters confirmed by the log.

There is no asterisk form for these two commands, and illegal asterisk calls do not provide counter navigation, renaming, or name completion; `counterwithin*` and `counterwithout*` still support counter operations.

## Label assignment

`setcounterref` / `addtocounterref`, `setcounterpageref` / `addtocounterpageref` recognize the first counter parameter and the second label parameter respectively, and provide respective completion, navigation, referencing, renaming, compilation diagnostics and spelling repair. Counters and labels with the same name still belong to different symbols. Repair and renaming only change the corresponding parameters; command snippets, signature help, and completion of cross-line labels are supported. Commonly used asterisked references (such as `ref*`, `pageref*`) also support name completion and signature help.
