# latex-lsp

用 Rust 实现的轻量 LaTeX Language Server，通过 stdio 提供 LSP 服务。无需安装 TeX 发行版即可使用编辑功能。

## 功能

- 文档同步：完整或增量更新，使用 UTF-16 位置，支持中文、emoji 和 CRLF；拒绝无效编辑和过期版本。
- 颜色预览与取色器：标准 `documentColor` / `colorPresentation` 支持 `definecolor`、`color`、`textcolor`、`colorbox` 和 `pagecolor` 中明确指定的 `rgb`、`RGB`、`HTML`、`gray`、`cmyk` 字面颜色。编辑保留命令、名称、周围空白、注释和正文；灰度颜色改为彩色时同步将模型改为 `rgb`。不推断命名颜色、混合表达式或动态宏，不提供透明度编辑。
- 这些颜色命令也提供补全片段、悬停说明和参数提示，补全时保留已有参数。`definecolor` 区分可选类型、名称、可选前缀、模型和颜色值；颜色命令的可选参数在首个未受花括号保护的 `]` 处结束，完成调用后的正文不再触发参数提示。
- 命名颜色支持跨文件定义跳转、悬停、引用查找、高亮、符号列表、语义高亮和版本化重命名：识别 `definecolor`、`providecolor`、`xdefinecolor`、`colorlet` 声明，以及常用文本、盒子、页面、表格颜色和颜色提取/转换命令中的静态名称。混色如 `-accent!35!red!50!white` 仅编辑名称，保留反色符号、比例、同名正文、宏、标签、注释和逐字内容。颜色参数补全提供内置颜色及当前项目声明，支持词中替换和未闭合分组；后三种声明也提供片段和参数提示。
- 名称周围及混色运算符之间的注释也支持导航、重命名和补全，保留注释、续行缩进、CRLF 和比例；静态类型、前缀及模型参数也可带注释。名称自身被注释拆开时不自动改名或替换，避免单次编辑删除注释。
- 颜色重命名支持的名称以 ASCII 字母、数字或下划线开头，后续允许字母、数字、下划线、短横线和点；仅消除 TeX 注释及其续行缩进，不归一化其他名称空白。拒绝多重定义、内置颜色或既有名称冲突，以及共享文件在不同项目中指向不同定义的情况。遇到动态颜色参数、命令重定义、间接调用、批量声明或未解析的 hyperref/TikZ/tcolorbox 颜色设置时拒绝改名；该静态分析不执行 TeX 宏展开。
- 识别到颜色命令作为其他用户宏的实参时，准备重命名和重命名都会拒绝，避免把宏输出的普通文本当作颜色名修改。参数分析汇总当前项目内的宏签名，支持跨文件无参宏、已完成的参数调用及常见字体切换、遮罩、混色、表格和颜色输出命令；其他项目的同名宏不参与分析。
- 用户宏的必选分组、可选参数和 xparse 分隔参数中的命令也按实参处理，颜色重命名和编译错误修复不会将其误判为直接执行的命令；签名未知时，对可确认的分组采用同样的规则。内置格式命令及其纯静态别名仍正常分析正文，例如 `textbf` 内的颜色引用可继续改名；调用完成后的后续命令也正常参与分析。此规则不求值用户宏是否执行、丢弃或展示其参数。
- 零参数宏的分组正文若只含一个控制词（允许外围空白与注释），颜色分析会沿静态别名链继承目标的参数规则，包括可选参数、星号、标志及分隔参数。支持传统声明、TeX 定义和 xparse 空参数规格；循环、未知目标、重定义和展开式定义保守回退，真正的空宏及无参字体切换仍可正常使用。此规则不求值任意宏正文。
- 编译后的 xcolor `Undefined color` 错误可定位到已确认的静态名称，并从当前项目的颜色定义和内置颜色中提供拼写修复。支持常见颜色选择、盒子、页面、别名、遮罩及颜色提取/转换调用，修复保留混色比例、反色符号、正文、注释和 CRLF，并拒绝过期编辑。源码回显不完整或不唯一、单次调用中重复的名称、宏展开及延迟生效的混色设置保留行级诊断。
- xcolor 明确报告 `Undefined color model` 时，静态模型名也支持精确定位和拼写修复，例如 `rbg` → `rgb`、`HTLM` → `HTML`、`gary` → `gray`。支持颜色声明及常见文本、页面、盒子的模型参数，包括 `fcolorbox` 的独立背景模型；编辑保留颜色值和正文。模型或分量含宏、同一调用中多个模型同名、命令重定义或源码回显不明确时保留行级诊断。
- 颜色诊断复用宏签名识别未分组的控制序列实参，避免把作为参数传递的颜色命令误判为直接调用。支持传统声明、无分隔符 TeX 宏和 xparse 可选参数、标志及分隔参数；正常的已完成调用、字体切换和颜色提取/转换输出参数保留精确修复。无法确认前置宏参数边界时保留行级诊断；该分析不执行宏展开。
- 宏实参分析也识别 TeX 定义中的静态 ASCII 前缀和分隔参数，兼容 `def`、`gdef`、`edef`、`xdef` 及对应的 etoolbox 命名定义。分隔控制词按完整 token 匹配，跳过受花括号保护的同名分隔符，支持普通空格、Tab、换行、注释续行、多 token 分隔符和静态别名；连续排版空白按 TeX 空格 token 归一化，控制词后的词法空白忽略，注释续行不产生空格。调用结束后的正常命令继续参与诊断和编辑。此规则仅用于识别被宏消费的命令，不增加这类宏的参数提示或补全片段；不推断含空段落、非 ASCII、`^^` 写法或超过 64 个分隔 token 的参数文本。
- 静态 `\csuse{名称}` 和字面 `\csname 名称\endcsname` 调用也使用当前项目内的宏签名识别实参，覆盖分组、可选参数、xparse 标志、TeX 分隔参数及静态别名。保留名称组后具有语义的空格，并忽略 `endcsname` 后的词法空白；命名声明不当作调用，相关命名命令被重定义时不推断调用目标。调用结束后的正常文件修复和颜色重命名仍可使用；不执行动态名称或任意宏展开。
- 自定义环境的起始命令也参与宏实参分析，支持传统与 xparse 声明的必选、可选和分隔参数，以及直接调用、静态命名调用和别名。`begin{环境名}` 按环境参数的实际边界读取，也识别静态 `\csuse{begin}`、字面 `\csname begin\endcsname` 和纯别名调用后的环境名；`begin` 被重定义或目标不确定时不推断环境参数。已完成参数后的正文继续参与文件修复和颜色重命名；环境起止命令的纯静态别名也继承目标的参数规则，结束调用后的正常命令继续参与分析；环境名、生成的结束命令与普通宏名发生冲突时保留歧义。暂停父文件中的环境声明也参与冲突检查，并在应用旧修复前重新校验。环境声明本身提供名称、参数规格及起止代码的参数提示。声明的参数规格和默认值也按数据处理，起止代码中的正常颜色引用仍可改名。此规则不执行环境正文或动态宏展开。
- 环境名也支持未分组的 ASCII 单字符参数（例如 `\begin x`），兼容静态命名调用与别名；环境实参继续按该环境的参数规则分析。环境配对诊断、跳转、引用和重命名识别这一名称，重命名时自动补入花括号，以支持多字符新名称；不推断未分组的非 ASCII 字符、控制序列或 `^^` 写法。
- 环境引用、跳转和重命名也识别静态 `\csuse{begin/end}`、字面 `\csname begin/end\endcsname` 及纯静态别名后的环境名组，保留注释与版本化编辑。别名按各主文档的项目范围解析；共享文件中的同一位置在不同项目中含义不一致，或间接环境调用被当作宏实参时，拒绝重命名以避免遗漏或误改。动态名称和任意宏正文不执行展开。
- 静态 `\csuse{input/include}`、字面 `\csname input/include\endcsname` 及纯别名也参与源码依赖发现、文件链接、定义跳转和跨文件环境配对，首次编译前即可索引已载入源码中的定义。本地宏包与嵌套输入提供的别名按各主文档解析；作为宏实参或处于未执行定义正文的输入不建立间接依赖。这些调用的文件名也提供路径补全，支持未闭合分组、文件名周围的注释、目录后缀以及未分组或引号形式的空格与 Unicode 名称。补全按选定主文档解析别名，未选定主文档时要求各项目对调用含义一致。文件重命名保留调用形式和注释，未分组的 `input` 文件名改为含空格名称时补入花括号，并保留原文件名终止空白的语义，`include` 保留扩展名限制；共享位置含义不一致时拒绝不一致的编辑。动态名称、任意宏展开和无法稳定确定的依赖图不作推断。
- 环境配对诊断与修复也按项目解析静态命名调用及别名，普通与间接起止调用可以混用；意外结束调用的删除修复覆盖完整命令，缺失结束调用则在外层环境结束前补齐。共享文件只提供各项目一致的配对修复，宏数据与不确定执行的定义正文按名称保留不确定性，正文中的动态环境参数也不当作实际环境名；其他名称的真实配对错误、逐字环境错误和编译诊断仍保留。旧修复应用前重新解析依赖中的别名，避免别名变化后删除合法调用。配对按主文档中静态 `\input`、`\include` 的出现顺序跨文件执行，并支持嵌套输入；跨文件缺失结束调用的修复指向实际关闭位置，并关联起始文件。重复输入和共享文件的编辑必须在各次执行及各主文档中一致；循环、条件、动态输入或语义不确定的 `\endinput` 不使用不完整序列生成配对修复。不执行任意宏展开。
- 编译前捕获显式源码依赖快照，颜色、计数器、环境及缺失输入文件、宏包、文档类的诊断可使用错误发生前已载入的项目宏签名，支持跨文件无参宏、静态别名及已完成调用。缺失输入文件的错误也识别静态命名调用与纯别名，定位到文件名并提供保留调用形式、注释及引号的拼写修复；未分组文件名改为含空格或 Unicode 名称时自动补入花括号。静态间接 `include` 缺失章节时，即使编译成功，也会在文件名处给出警告和拼写修复；辅助文件的 `No file` 消息不当作缺失章节，修复遵守 `includeonly`。 静态命名调用和纯别名的 `usepackage`、`RequirePackage`、`RequirePackageWithOptions` 也发现本地宏包依赖，并为缺失宏包定位文件名、提供拼写修复，保留选项、逗号列表、注释和最小版本参数；这些间接宏包调用也支持路径补全、文件链接、定义跳转和文件重命名，编辑保留选项、列表、注释和最小版本参数；共享文件的修改须在各主文档中一致。列表中的路径若改为含逗号的名称，会拒绝重命名，避免一个文件名变成多个列表项。动态列表和不确定依赖图不作推断。诊断记录当时的宏来源，修复前按该来源重新核对当前参数边界和别名含义；后续载入、未执行的包含、仅作代码展示的文件和其他项目不参与归因。仍暂停在包含调用处的父文件不向子文件错误提供签名；其声明会使同名宏及依赖它的别名保持参数边界不确定，修复前也会重新检查这些冲突。依赖已变化、当前报错文件不在快照中，或已载入源码含动态文件加载（包括宏定义中的动态加载）时保留行级诊断，避免根据不完整的宏集合推断参数边界。
- `definecolor` 的颜色预览和取色编辑也支持空类型、`[named]` 及静态可选前缀，编辑保留这些参数。`[ps]` 类型和自定义类型可能改变实际显示颜色，暂不提供颜色预览或取色编辑；动态前缀同样跳过。
- `fcolorbox` 支持补全、悬停、参数提示，以及边框和背景两处字面颜色的预览、取色编辑。支持两者共用模型或各自指定模型；共用灰度模型时，将其中一个改为彩色会补入独立的背景模型，保留另一处的实际颜色。
- `cmyk` 按 xcolor 默认规则转换为 RGB 预览，取色编辑保留 CMYK 模型；颜色未改变时保留原四个分量及黑色分量，改变颜色时使用默认黑色分离。共用 CMYK 模型的边框和背景可分别编辑，另一处颜色与分量保持不变。
- LSP 3.17 诊断拉取：协商支持 `textDocument/diagnostic` 和 `workspace/diagnostic`，合并实时、项目重复定义和编译诊断；返回结果 ID，未变更时省略条目，关闭后回到磁盘内容，移动或删除文件后清除旧位置的结果。支持客户端刷新请求，编译完成和跨文件编辑后重新拉取；旧客户端继续接收推送诊断。结果缓存按连接隔离并限制大小。
- 实时诊断：未闭合/多余花括号、环境不匹配、同一文件内重复的标签或文献键，以及同一项目中跨文件重复的标签和文献键。
- 快速修复：补全缺失花括号、闭合环境、删除多余的闭合符号，以及编译诊断中标签、文献键、命令、环境、计数器和 PDF 目标的拼写建议；支持版本化编辑和旧客户端的命令式操作，拒绝过期修复。同一位置的多条编译警告均可单独请求修复，批量请求合并相同替换。
- 宏包列表中的 TeX 注释会保留：`usepackage`、`RequirePackage` 和 `RequirePackageWithOptions` 的依赖追踪、链接、路径补全和文件/目录改名只使用真实名称；已确认的缺失宏包错误定位到具体名称并提供拼写修复。可选参数在首个未受花括号保护的 `]` 处结束，`WithOptions` 不接受前置选项。动态、嵌套或由注释拼接的名称不作推断；错误定位与修复要求整个列表均为静态名称。
- 文档类名称按单个文件处理，支持 `documentclass`、`LoadClass` 和 `LoadClassWithOptions` 名称前后的注释。导航、补全、文件/目录改名、缺失类错误定位与拼写修复保留名称中的空格和逗号，并与参数提示共用首个未受花括号保护的 `]` 边界；不将类名当作宏包列表拆分，也不将含空格的类名改为另一个紧凑名称。
- 图片路径修复：将可确认的静态 `\includegraphics` 缺图错误定位到路径，按编译根目录和项目内的 `\graphicspath` 提供文件名拼写建议。
- 宏包和文档类路径修复：确认静态加载名称后，将缺失文件错误定位到具体名称，提供本地 `.sty` / `.cls` 文件的拼写建议，并修复误填完整文件名造成的重复后缀。
- 缺失输入文件、宏包和文档类的精确诊断及路径修复会核对宏实参边界，跳过作为其他宏未分组参数的 `input` 及包/类加载命令。支持项目宏签名和来源重校验；命令被重定义或参数边界无法确认时保留行级诊断，避免修改宏调用中未执行的文件名。
- BibTeX 样式路径支持名称前后的 TeX 注释，导航、路径补全及文件/目录改名只修改真实名称，保留注释和 CRLF。`bibliographystyle` 按单个文件名处理，支持名称中的逗号；注释后行首缩进按 TeX 规则忽略，普通首尾空白、空行、动态宏和由注释拼接的名称不作静态推断。
- 补全：常用 LaTeX 命令、环境、用户命令、跨文件标签、BibTeX 文献键及输入文件/图片/本地包等路径。支持词中替换，根据客户端能力提供 snippet，并保留已有参数；引用和路径的可选参数含有嵌套命令时，仍可找到当前的键名或文件参数。
- 悬浮提示：内置命令说明、标签/文献/自定义命令的定义位置。
- 内置命令补全保留已有的无花括号 ASCII 实参，例如 `\frac12` 和 `\textbf\payload`；在数学、对齐或环境结束符前仍插入参数占位符。用户宏使用相同规则，显式声明的标志和分隔符优先。
- 参数提示：常用命令、环境及跨文件用户宏/环境的签名，区分必选/可选参数，跟踪嵌套调用中的当前参数。传统 `newcommand` / `renewcommand` / `providecommand`、`DeclareRobustCommand` 和 etoolbox 的 robust 变体，以及 `newenvironment` / `renewenvironment` 的声明本身也提示名称、参数数量、默认值及定义正文，识别星号和两种宏名称分组形式；补全保留已有的控制词名称。
- 手写文献 `\bibitem[label]{key}` 提示可选显示标签与必选文献键；显示标签在首个未受花括号保护的 `]` 处结束，保留其中的字面量 `[`。键结束后的正文、多余可选标签和不支持的星号不会继续触发键参数提示。
- `bibentry` 宏包的 `\bibentry{key}` 正文内文献引用支持导航、悬停、引用查找、补全、参数提示、语义高亮和跨文件重命名；实际编译的缺失文献警告可定位到键名并提供拼写修复。按单个文献键处理，保留注释、条目正文和同名标签；不把键列表、动态名称或不支持的星号、可选说明当作可编辑键。
- `\nobibliography{databases}` 支持逗号分隔的文献库路径、参数提示、路径补全、导航、依赖追踪和文件改名；保留列表分隔空白及扩展名写法，按 BibTeX 规则忽略路径中的 TeX 空白并补全 `.bib`。不带参数的 `\nobibliography*` 不会将后续分组当作文献库，也不接受可选说明。

- `\hyperdef[label]{类别}{名称}{文字}` 的可选标签作为声明加入索引，与普通标签共用导航、补全、重复定义检查和安全重命名。重命名保留 PDF 目标的类别、名称和显示文字；支持 `[{label}]` 保护形式，并提供命令片段及参数提示。
- PDF 内部锚点使用独立命名空间：`\hypertarget`、`\hyperlink`，以及 `\hyperdef` / `\hyperref{}{类别}{名称}{文字}` 的静态组合目标支持导航、引用、高亮、悬停和跨文件安全重命名。`\hyperlink` 提供完整目标名补全，声明进入符号列表及项目内重复检查。同名标签保持独立；组合目标按 `类别.名称` 匹配，改名时保留参数分隔符、注释、换行、可选标签和显示文字，必要时将完整新名称放入空类别后的名称参数。不展开宏，也不推断章节等命令自动生成的锚点。
- `\pdfbookmark[层级]{标题}{名称}` 的静态目标按实际的 `名称.层级` 索引，层级默认 `0`，保留前导零和正负号；支持上述目标编辑功能、编译诊断、拼写候选、命令片段及参数提示。重命名使用完整目标名，例如 `chapter.intro.1`，同步更新名称、层级和链接，必要时补入可选层级，保留标题、注释和同名标签。新名称须带合法数字层级后缀，层级为不小于 `-3` 的 TeX 整数；动态层级、动态名称及依赖当前层级的 `currentpdfbookmark` 等命令不作推断。
- 查找引用：标签、文献键、自定义命令；支持包含或排除定义。
- `cleveref` 的 `crefrange` / `Crefrange`、`cpagerefrange` / `Cpagerefrange` 及星号形式支持两个端点的标签导航、补全、悬停、引用查找和跨文件重命名，并提供参数提示、命令片段、语义高亮和编译警告的拼写修复。端点按单个标签处理，保留星号、注释和换行；不将无效的可选说明当作标签。
- `cleveref` 的 `cpageref` / `Cpageref` 页码列表及星号形式使用相同的标签编辑功能，逐个识别逗号分隔的标签；补全、重命名和编译警告修复保留其他标签、分隔逗号和空白。
  标签列表补全支持跨行调用，`cref` / `Cref` 同样遵循实际的星号与参数边界，不在无效的可选说明之后提供标签编辑。
  文献引用的键列表也支持跨行补全，包括普通 `cite`、natbib 和 biblatex 的已支持命令；只替换当前键，保留其他文献键、说明参数、换行和列表空白。
  标签与文献列表中，键名前后的 TeX 注释会保留，注释里的逗号和括号不参与键名解析；导航、重命名、补全、编译警告修复和语义高亮共用实际源码范围。宏展开、嵌套分组和由注释拼接的非连续键名不作静态推断。
  单标签的声明、引用、范围端点，以及 hyperref 和 refcount 的标签参数也识别名称前后的 TeX 注释。导航和重命名保留名称中的普通空白语义；接受补全时单独清除旧名称外围空白并保留注释，编译警告仍按实际闭合参数的行号核对位置。
  hyperref 的保护花括号内外均可保留注释；补全或改名为含方括号的名称后，仍可继续导航和重命名。
  natbib 的 `defcitealias` 单文献键同样支持前后注释；导航、补全、引用查找和文献重命名保留注释与别名显示文字，不合并含普通空白、宏或由注释拼接的动态键名。
  手写 `bibitem` 声明也识别键名前后的注释，引用可导航到实际键名并参与文献重命名、语义高亮、重复定义检查和拼写修复；保留可选文献标签和条目正文，跳过需要宏展开或含语义空白的声明。
  `bibitem` 最多读取一个可选文献标签，并在首个未受花括号保护的 `]` 处结束；标签中的字面量 `[` 不会吞掉文献键，多余可选标签、未闭合标签或不支持的星号之后的正文不会被当作文献键编辑。
- 文档高亮：区分当前文件中的定义和引用；选择范围可逐级扩展到词、参数、命令、章节和整篇文档。
- 语义高亮：支持全文及指定范围的标准 LSP semantic tokens，区分命令、寄存器、环境、标签/PDF 目标/文献键、URL、逐字文本和注释，并标记静态声明。复用已有名称索引，跳过动态名称和普通正文；BibTeX 提供文献键、条目间引用及顶层注释高亮。输出为不重叠的单行 UTF-16 token，兼容中文、emoji、CRLF 和增量编辑。
- 语义高亮增量结果：支持 `semanticTokens/full/delta`，只传回变化的 token 段；未变化时返回空编辑。快照按文档和结果 ID 隔离，关闭文档后清除；过期 ID、缓存淘汰或大文档自动回退为全文结果。每个连接最多保留 16 份快照、合计 65,536 个 token，范围查询不影响全文快照。
  范围查询兼容编辑器使用的文件末尾视口和超出行尾的列位置，包括没有末尾换行的文件；仍拒绝代理项中间的位置，文档编辑继续使用严格位置校验。
- 环境名称联动编辑：支持标准 `textDocument/linkedEditingRange`，同步当前匹配的 `\begin{name}` 与 `\end{name}` 名称，区分嵌套和重复环境；支持中文、星号、UTF-16、CRLF 和增量编辑。常见逐字环境只联动真实边界，不编辑正文中的假命令；结构不匹配、动态名称、声明名称、注释和普通正文不提供联动范围。
- 跨文件重命名：标签、BibTeX 文献键、自定义命令和环境；环境同步修改声明与 `\begin` / `\end`，文献键同步更新条目间引用。支持准备重命名、定义歧义/重名检查及版本化工作区编辑，跳过注释和逐字文本。
- 定理重命名：维护 `\newtheorem` 的共享编号与编号重置关系、计数器操作、派生命令及 cleveref 名称；区分自有计数器、共享计数器和无编号定理，可从关联命令跳转或发起重命名。
- 文件/目录重命名：通过 `workspace/willRenameFiles` 更新输入文件、文献库、BibTeX 样式、本地包/类、图片及 `% !TeX root` 路径；目录移动会重算内部相对路径，保留省略扩展名的写法。
  `includeonly` 的章节列表识别文件名前后的 TeX 注释，导航、路径补全和文件/目录改名保留注释、列表分隔符、CRLF 及文件名内部空格；选择列表本身不会加载章节。缺失章节的 PDF 过期检查与拼写修复使用相同解析，遇到动态或不连续名称时保守处理。
- 文件/目录创建与删除：处理标准 `workspace/didCreateFiles` / `workspace/didDeleteFiles` 通知，递归更新来源索引，刷新导航、补全和重复定义诊断；保留未保存的缓冲区，取消受影响的编译并清除旧编译诊断。无需文件监听也能同步编辑器中的文件操作，继续保留 recorder 输入以检查旧 PDF 是否过期。
- 文档符号：章节标题、标签、自定义命令、手写 `bibitem` 文献键和 BibTeX 条目；根据客户端能力返回层级结构或平铺列表。手写文献键按所在章节组织，使用实际键名范围，也参与工作区符号搜索；未保存的增量编辑会同步更新结果。
- 工作区符号搜索：跨文件搜索章节、标签、宏和文献键，支持中文、不区分大小写及子序列匹配，按相关性返回最多 256 项。
- 文档折叠：章节、嵌套环境、多行花括号、连续注释和逐字环境，遵守客户端折叠数量限制。
- 文档链接：输入文件、文献库、本地包/文档类、图片及 `\url` / `\href`；四参数 `\hyperref{URL}{类别}{名称}{文字}` 会按实际 PDF 链接附加 `#类别.名称` 目标，保留 URL 转义和已有片段，跳过需要宏展开的目标。输入文件、文献库及本地包/类先在编译主文档目录查找，再尝试当前文档目录；图片按下文的 `\graphicspath` 规则查找。`% !TeX root` 始终相对于声明所在文档。
- 工作区索引：扫描 `.tex`、`.ltx`、`.bib`、`.bst`、`.sty`、`.cls`、`.def`、`.clo`；跟踪文件变更，优先使用编辑器中未保存的内容。
- 数据和代码文件依赖：编译 recorder 实际读取的 CSV、TSV、DAT、JSON、XML、YAML、YML 和 TXT，以及常见代码、配置文件参与内容快照、过期 PDF 检查、SyncTeX 校验和编译取消，包括工作区外的共享输入。监听扩展名不区分大小写；仅作为数据读取的文件不进入 LaTeX 符号索引，显式 `\\input{notes.txt}` 等源码包含仍正常索引。符号链接别名的图片/数据类型在规范化后仍会保留，目标没有扩展名或使用 `.tex` 等后缀时，也能跟踪内容变化并保持数据与源码索引的区别。
- 后台编译：支持 latexmk、pdfLaTeX、XeLaTeX、LuaLaTeX、Tectonic 和自定义工具；根文件识别、取消、超时、状态查询、编辑器原生进度显示和可选的保存后编译。
- 文档内编译入口：支持标准 CodeLens，在主文件或已关联的章节、包等 TeX 来源中直接编译项目。遵守根文件配置和 `% !TeX root` 指令；共享来源可分别选择各主文档，多工作区文件夹中的同名主文件用完整路径区分。每次请求重新核对根文件，最多返回 32 个入口；未保存的独立文档、无所属项目的片段和不可用的显式根不提供入口。

- SyncTeX 查询：源码行定位 PDF 页码/坐标，以及 PDF 坐标反查源码行；返回数据供编辑器或 PDF 预览插件使用，检查未保存来源和过期产物。

本地文件 URI 的百分号编码统一为同一文档身份，兼容编辑器使用小写编码的中文路径及转义后的 ASCII 文件名；文档同步、项目索引、编译诊断、导航和版本化编辑共用同一份内容，保留文件名大小写。

自动根文件识别只考虑磁盘上仍可编译的 `.tex` / `.ltx` 主文档，文件已删除而通知尚未到达时也会重新检查。宏包、文档类和支持文件中的文档示例不会形成额外编译根，从这些文件发起编译时使用所属主文档；显式根配置、魔法注释及直接编译已删除主文件的错误继续保留，不静默改用其他项目。

相对 `build.rootFile` 可指向工作区外的主文档。编译事件返回的已配置根 URI 可直接用于状态查询、取消或再次编译，不会按根文件所在目录再次解释相对配置；兼容重叠的工作区文件夹。根文件删除后保留缺失错误，避免误用其他目录中的同名文件。

解析时跳过 `%` 注释、`\verb`、`\lstinline` 和常见逐字环境（`verbatim`、`lstlisting`、`minted`、`comment`，以及 FancyVerb 的 `Verbatim`、`LVerbatim`、`BVerbatim`、`SaveVerbatim`、`VerbatimOut` 和各自的星号形式）。逐字环境中的示例标签、命令和文件包含不会进入源码索引，重命名保留其中的字面内容；支持环境名称补全、折叠、逐字高亮和未闭合环境修复。不模拟 `commandchars`、自定义环境或内部宏带来的执行行为。FancyVerb 每行只核对第一个字面关闭标记；同一行先出现其他环境的关闭标记时，后续同名标记继续作为展示内容，不会提前恢复源码索引。关闭标记后同一行被 FancyVerb 丢弃的内容也不参与符号索引或编辑；下一行恢复正常源码解析，编译器报告的行尾多余内容错误仍会保留。环境头部的选项及保存名称按参数边界读取；其中的字面关闭标记不会结束正文，支持多行选项和注释续行。`UseVerb`、`UseVerbatim`、`LUseVerbatim`、`BUseVerbatim`、`UseMVerb`、`pUseMVerb` 的保存名称参数同样按数据处理，前面的格式选项继续正常解析。`\SaveVerb{name}|text|`、`\SaveGVerb{name}|text|` 与 `\Verb|text|` 的行内正文也按字面内容处理，支持星号、一次可选参数、注释续行、分组分隔符和 Unicode 分隔符；缺少结束分隔符时在行尾恢复源码解析。`aftersave`、`formatcom` 等选项中的命令仍正常索引，重命名保留展示正文。

保存文本名称支持定义跳转、引用、悬停、补全和版本化重命名。`SaveVerb` 与 `SaveVerbatim` 共用名称，`UseVerb` 及三个 `UseVerbatim` 命令读取这一组；`SaveGVerb` 与 `UseMVerb`、`pUseMVerb` 使用另一组。名称按完整字面值匹配，保留首尾空格、逗号和 Unicode；改写裸参数时自动补花括号。共享文件的修改会覆盖所有依赖项目，并检查各项目的定义与命名冲突。空名称、宏展开、名称内的注释及跨行名称暂不推断；包含动态名称的调用、相关重定义、可执行字符设置、无法静态确认的 `SaveMVerb` 定义或项目歧义会阻止自动重命名。

动态保存名称中的普通宏引用仍支持跳转、引用查询、悬停、补全和宏重命名，例如 `\UseVerb{\keyname}`；也识别其中字面 `\csname keyname\endcsname` 与 `\csuse{keyname}` 的宏引用。修改宏名称会同步更新这些使用位置，但不推断宏展开得到的保存名称值。名称参数不会产生 LaTeX 声明、标签或文件依赖；注释、逐字正文、`\detokenize{...}` 内容和 `\string` 的下一个 token 保持原样。

`SaveVerb`、`SaveGVerb` 和各读取命令的名称参数仅包含一个普通宏时，编译器确认的未定义宏错误可精确定位到该命令，并提供项目内候选的版本化拼写修复。定位同时核对 FancyVerb 展开帧和源码回显；用户宏包装、混合名称、额外展开帧及无法唯一匹配的缩短回显继续使用整行诊断。

名称参数中的已知派生命令会关联到所属符号，例如 `\theexercise`、字面 `\csname c@exercise\endcsname` 或 `\csuse{theexercise}` 关联到计数器 `exercise`；导航与重命名保留 `the`、`c@` 等派生前缀。定理环境、普通环境和条件开关的已知派生命令同样适用，并沿用共享项目冲突检查；直接控制词中的基础名称仍须使用 TeX 命令字母。

保存名称内的 `\arabic`、`\roman`、`\Roman`、`\alph`、`\Alph`、`\fnsymbol` 和 `\value` 也跟踪其静态计数器参数，支持跳转、引用、悬停和重命名；定理计数器继续归属于原环境，裸参数改名时自动补花括号。参数按完整字面值匹配，动态参数及包含语义空白的参数不推断；注释和字面转换内容继续保持原样。

这些命令的分组参数提供计数器名称补全，包含内置计数器、项目计数器和定理计数器；共享定义进入所属项目的候选，独立论文的名称保持隔离。选择补全会替换整个参数内容，跨行参数使用位于请求行的主编辑和必要的额外编辑；支持尚未闭合的名称输入。

保存名称中的单个裸 ASCII 计数器参数也提供补全，例如将 `\arabic x` 补全为 `\arabic{xlong}`；替换时自动补花括号，只修改该参数 token，保留其后的名称文字、注释和换行。

LaTeX 内核的 `NewExpandableDocumentCommand`、`RenewExpandableDocumentCommand`、`ProvideExpandableDocumentCommand` 和 `DeclareExpandableDocumentCommand` 与普通文档命令共用宏导航、引用、重命名和补全，兼容带花括号或裸命令目标及静态 `csname` 形式。声明提供命令、参数规格、定义体的参数提示；调用支持 `m`、`o`、`O`、`s`、`t` 以及 `d/D/r/R` 分隔参数规格及修饰符，补全保留可选参数默认值。复杂规格继续保守回退，不执行宏展开。

`NewCommandCopy`、`RenewCommandCopy` 和 `DeclareCommandCopy` 支持复制目标的导航、引用、补全和重命名，并提供声明参数提示与片段。复制目标是独立宏；重命名原命令时维护复制声明的来源参数，重命名副本时只更新副本的声明与调用。兼容带花括号或裸命令参数，以及目标的静态 `csname` 写法，保留注释和逐字内容。

`NewEnvironmentCopy`、`RenewEnvironmentCopy` 和 `DeclareEnvironmentCopy` 支持环境导航、引用、重命名、语义高亮及声明参数提示。第二个参数按来源环境处理，支持完整、未完成和跨行名称的补全；重命名来源时同步更新该参数。副本的 `begin` / `end`、直接生成的命令和静态 `csname` 调用使用副本自己的名称；复制定理时继续使用原计数器，不推断副本拥有同名计数器。含语义空白或动态的来源名称不作静态匹配。

`DeclareTextCommand` / `ProvideTextCommand` 及其 `Default` 形式支持文本宏的导航、引用、重命名、声明参数提示和调用参数推断。编码参数独立于宏实参；补全省略可选参数以保留默认值。`DeclareTextSymbol` 的零参数符号与 `DeclareTextAccent` 的单参数重音命令同样进入索引，兼容裸命令或花括号目标，保留编码、字符槽位和定义体。

未定义标签或文献的编译警告会尽量标出具体键名，包括列表中的单个键、同一行的多处引用，以及使用单引号的包警告；无法从源码明确匹配时保留整行位置。日志文件上下文支持 `.def`、`.clo` 等来源、带空格/括号的路径，以及 TeX 自动换行的长文件名。

显式“文件名:行号:错误”跨行时，恢复实际文件路径和行号，包括文件扩展名或行号分隔符恰好被拆开的情况；传统 `!` 错误和显式位置错误的消息也支持按字节折行，保留单词内部的拼接与原有空格。恢复不会跨越相邻诊断、文件切换、TeX 源码上下文或大日志的省略边界。

传统括号式日志的折行文件名在前半段恰好也是另一个现存文件名时，继续核对后续内容是否组成更长的实际来源，避免把长文件中的错误或警告归到同名前缀文件。兼容括号、中文及有无短文件前缀的情况；长来源已消失时保持未确认状态，不改用短前缀文件。完整的引号文件名仍按引号边界处理。

缺失输入文件或宏包造成 `Emergency stop` 时，同时保留包含缺失文件名的原始错误；兼容传统和显式文件行号日志，并保留子文件归属及错误发生时的项目宏上下文。只有同一来源、连续的文件查找提示才能关联终止位置；文件切换、其他诊断、日志截断或超出查找范围时，保留原错误并使用保守的文件首行位置。

未定义控制序列的错误会利用 TeX 的 `l.N` 源码上下文，精确标出直接调用的命令；同一行的多个错误分别保留，使用 UTF-16 位置。省略过长前缀的上下文须能唯一匹配完整命令；宏展开栈、源码不匹配或上下文不完整时保留整行诊断。

数学模式及盒子中的直接未定义命令也支持精确诊断和拼写修复。TeX 额外输出单个 `<recently read>` 命令时，会同时核对该字面命令、紧随其后的行号、源码前缀及当前来源；其他展开帧、重复的省略上下文或不匹配的命令继续回退整行，避免将宏内部错误归到有效调用上。

带文件名和行号的命令、环境、计数器及缺失输入文件错误，只在日志所报源文件可解析为实际文件时使用源码上下文。来源路径不存在或实际为目录时，错误仍在主文件显示，保留整行位置，避免借用主文件中的同名文本生成精确修复。

传统括号式日志进入的子文件已消失、不是实际文件或路径无法解析时，也保留来源未确认状态。错误、引用与盒子警告不会借用父文件的源码范围、拼写候选或包含关系；嵌套的可解析来源和退出后的父文件继续正常定位。

同样的来源校验也用于带文件名和行号的标签、文献键、PDF 目标、缺失章节及盒子警告：来源无法确认时保留原消息和整行位置，不借用主文件中的名称或跨行范围，也不提供对应的拼写编辑。PDF 引擎、盒子和缺字等警告即使使用这种文件行号格式，也继续按警告统计。

编译输出或日志的中段被省略后，传统错误和警告在重新观察到可解析来源前保留“来源未确认”状态，以有效整行范围显示，不借用主文件名称生成精确修复。明确带文件名和行号的诊断仍可独立确认来源；进入可解析子文件或主文件后恢复正常定位。

日志报告第 0 行或超出文件范围的行号时，诊断保留原始行号数据，并使用文件中有效的整行位置显示；不会将夹到首行或末行的同名文本视为精确位置，也不会据此提供修复或重新定位 PDF 目标。缺少行号的正常 PDF 输出警告仍按该次编译的实际输入定位。位置数据不同的诊断会分别发布，避免相同消息相互覆盖。

`LaTeX Error: Environment ... undefined.` 同样可精确标出 `begin` 的环境名称，识别标准 LaTeX 帮助提示、换行分隔的命令与实参，以及同一行的多处调用。截断上下文必须唯一匹配完整参数；动态名称、宏展开、忽略区域和源码不匹配时保留整行位置。精确诊断附带 `undefined-environment` 代码及环境名称数据。 `begin` / `end` 作为宏的未分组实参时保留行级位置，无法确认的重定义和动态来源同样不提供精确修复。环境诊断记录错误发生时的宏来源，修复前重新核对宏参数与配对边界；匹配结束标记时跳过被宏消费的环境控制序列。截断日志中的名称必须在源码行中唯一匹配，避免修改未执行分支中的同名文本。

pdfTeX 在输出 PDF 时的 `!pdfTeX error:` 也会显示具体编译诊断，例如缺失的 Type 1 字体文件；保留换行中的完整文件名和错误说明，省略通用的致命退出提示。没有源码行号时定位到主文档开头，避免猜测字体声明位置。

LuaTeX 等引擎的通用致命退出提示在已有具体错误时不再重复显示，编译结果摘要优先展示实际原因；日志没有更具体的错误时，仍保留通用退出错误。

PDF 驱动失败时，XeLaTeX 的 `xdvipdfmx` 和独立 `dvipdfmx` 的 fatal 消息及相关警告同样显示为编译诊断，包括仅写入 stderr 的错误。字体警告中连续的 `>>` 详情会合并，保留实际映射的字体文件名；驱动消息定位到主文档开头，不借用 TeX 子文件或后续行号。

`LaTeX Error: No counter '...' defined.` 可精确标出 `setcounter` / `addtocounter`、`stepcounter` / `refstepcounter` / `usecounter` 的静态计数器名称，保留数值表达式；兼容传统引号、多行参数和同一行的多处调用。宏展开、动态或残缺实参以及无法唯一核对的日志上下文保留整行位置，精确诊断附带 `undefined-counter` 代码及计数器名称数据。计数器命令作为宏的未分组实参时不视为直接调用；传统宏、TeX 宏、xparse 参数和静态别名使用该次错误发生前已载入的项目宏签名检查，动态来源或重定义无法确认时保留行级诊断。精确诊断记录宏来源，提供拼写修复前重新核对这些来源与完整调用；暂停的父文件只用于排除不确定声明，计数器候选仍来自当前项目。

父计数器、计数器别名及定理的共享/重置编号参数也使用精确计数器诊断，包括 `newcounter`、`newaliascnt`、`newtheorem` 和 `counterwithin` / `counterwithout` / `numberwithin` 的两个名称参数；识别星号和可选格式参数。修复只改动日志确认的名称，保留声明名称、标题、格式和参数分隔符；不建议形成自身别名或自身编号重置关系。可选计数器参数按 TeX 的方括号结束规则读取；含字面量 `[` 的父计数器、定理共享及重置计数器参与导航、补全和重命名。引入含 `]` 的名称时，父计数器及共享参数按需补足花括号保护，定理重置参数使用静态 `\detokenize{名称}`，使连续重命名保留计数器关系和编号格式。两个实参同名、动态名称或不完整调用无法确认具体位置时保留整行诊断。

`begin` 被不同名称的 `end` 闭合时，编译诊断会精确标出当前闭合名称，并以 `mismatched-environment-end` 代码附带实际名称与期望环境；识别带起始行号的 LaTeX 消息。同一行的多处闭合错误分别保留，宏展开或上下文不确定时保留整行位置。

编译确认的 `include` 文件缺失警告可提供最多 5 个相近文件名修复，按该次编译主文件的目录查找，保留路径前缀、扩展名写法、参数外空白、注释和换行；支持中文和含单个空格的文件名。只建议现存的 `.tex` 文件，跳过自身、主文件及索引中已知的包含循环；静态 `includeonly` 必须允许新名称，动态过滤列表不作推断。原文件已出现、候选消失、源码或版本改变后，旧修复失效；兼容版本化编辑和旧客户端命令。

缺失 `input` 文件的错误会核对 TeX 显示的源码上下文，精确标出静态文件名，并附带 `missing-input` 代码和文件名数据。支持花括号、裸文件名和引号形式，以及完整且唯一的省略前缀；宏展开、动态路径、残缺引号或不匹配的上下文保留整行位置。精确诊断同样提供最多 5 个现存 `.tex` 文件名建议，按诊断所属主文件目录查找；保留原有花括号和 ASCII 双引号路径，裸路径改成含空格的名称或裸/双引号路径改成非 ASCII 名称时自动使用花括号。`includeonly` 不限制普通 `input` 修复；建议遵守相同的版本、文件存在性、循环和请求资源限制。

`\usepackage` / `\RequirePackage` / `\RequirePackageWithOptions` 和 `\documentclass` / `\LoadClass` / `\LoadClassWithOptions` 的缺失文件错误支持 `missing-package` / `missing-class` 精确诊断，`data.file` 保存实际缺失文件，`data.loaderCommand` 保存加载命令。LaTeX 常在读取下一条命令后才发现文件缺失，服务器会核对这枚 token 或可选的最低版本参数，将位置还原到真正的加载名称；兼容跨行调用、宏包列表和 UTF-16。动态名称、宏展开栈、来源不确定或不唯一的省略上下文保留整行诊断。

这类诊断最多提供 5 个本地文件名建议，只在该次编译根目录及名称中显式指定的子目录查找 `.sty` / `.cls`，不推断系统宏包是否安装。修复保留其他宏包、选项、版本条件及参数外的空白；误写 `\usepackage{local.sty}` 而本地存在 `local.sty` 时，可改成正确的加载名称 `local`。版本、诊断、候选或原文件变化后，旧修复会失效；兼容版本化编辑和旧客户端命令。

重复加载宏包造成的 `Option clash for package ...` 错误也会定位到冲突的 `\usepackage` / `\RequirePackage` 名称，兼容包列表、跨行参数、可选版本和 UTF-16；即使 TeX 报告的是下一行的命令，仍会核对实际加载位置。确认来源后使用 `package-option-clash` 代码，并以 `data.package` / `data.loaderCommand` 提供包名和命令。动态名称、宏展开栈、歧义或无法验证的来源保留整行诊断。

日志中的冲突帮助块完整时，诊断还会显示已加载选项及本次请求选项，并在 `data.loadedOptions` / `data.requestedOptions` 中保存其原样字符串；空选项为 `""`，嵌套括号、逗号和空白保持不变。长包名、选项及帮助标题在词中换行时会拼回实际字符。详情必须紧邻本次源码上下文并匹配包名，读取受行数和字节限制；残缺帮助、其他错误、来源切换或截断标记不会被拼成选项详情。

环境不匹配的精确诊断可提供“闭合期望环境”的快速修复，只修改当前 `end` 名称。日志中的期望环境必须与同一文档的静态嵌套栈一致；未定义环境造成的连带错误、动态栈、先前交叉闭合、忽略区域及过期请求均不提供该修复。

对能够精确定位的未定义引用，快速修复会从当前项目的已知标签或文献中提供最多 5 个相近键名，支持相邻字符颠倒和中文。建议需要手动选择，只修改当前引用；跳过重复定义、宏生成的键名和已经存在的键，诊断过期后失效。

精确定位的未定义命令也提供最多 5 个拼写建议，来自内置命令、当前项目的自定义宏、寄存器和环境/计数器/布尔开关的派生命令。例如 `\\sectoin{Intro}` 可修复为 `\\section{Intro}`，保留原有实参。建议须手动选择；已有同名声明、候选有歧义、宏展开错误、源码上下文无法确认或诊断已过期时不提供修复。

`\ref`、`\pageref`、`\eqref`、`\cite` 和 `\nocite` 的键参数如果只含一个控制词（例如 `\ref{\keynme}`），编译器报告的未定义命令也可精确定位并提供宏名拼写修复。同样支持 hyperref 的 `Ref`、`autoref`、`autopageref`、`nameref` 和方括号标签形式 `hyperref`，varioref 的 `vref` / `Vref`，natbib 的大小写引文、作者、年份和别名引用命令，以及 `bibentry`。`hyperref` 标签可以有一层额外花括号，修复保留方括号、花括号和链接文字。 `subref`、`vpageref`、`getrefnumber`、`getpagerefnumber` 和 `refused` 的内部前缀错误也可定位到键参数中的宏名；仅接受与该接口匹配的编译错误帧，修复保留星号、说明参数及原有键表达式，不推断展开后的标签值。保留受支持的星号、可选说明及参数括号，不推断宏展开后的标签或文献键；混合键列表、间接展开、含语义空白的参数及无法确认的源码回显保留普通错误。 动态键参数中实际索引到的普通宏调用支持定义跳转、悬停、引用、高亮和版本化重命名；宏名与同名静态标签、文献键保持独立，参数中的注释和逐字文本不参与改名。

`\detokenize{...}` 的内容及 `\string` 消费的单个 token 不作为可执行命令索引；宏声明和命令复制中的控制序列操作数仍按命令处理。FancyVerb 文件名中的字面转换包装继续支持导航、补全、参数提示与文件重命名。

宏错误、未定义计数器错误及普通输入、图片、代码清单和逐字输入的缺失文件错误，其缩短源码回显必须在整行源码中对应唯一位置；相同后缀还出现在其他调用或逐字内容中时，保留整行错误，不提供可能改错调用的拼写修复。完整回显或唯一的缩短回显仍可区分重复名称。

refcount 的 `\getrefbykeydefault`、`\IfRefUndefinedExpandable`、`\IfRefUndefinedBabel` 及四种 `setcounterref`/`addtocounterref`/`setcounterpageref`/`addtocounterpageref` 接口也支持键参数内单个宏的精确编译错误和拼写修复。匹配各接口实际的参数消费边界及内部错误前缀，保留默认值、条件分支和计数器名称。字段选择参数为空时可提取引用编号；动态字段选择参数或计数器名称暂保留行级诊断。

精确定位的未定义环境提供内置环境与当前项目自定义环境的拼写建议，例如将 `algin` 改为 `align`。一次操作同时修改当前 `begin` 及同一文档内对应的 `end`，保留嵌套环境、其他同名调用、空白和正文。配对缺失、交叉闭合、动态嵌套或候选定义有歧义时不提供建议；支持版本化编辑及旧客户端操作，应用前重新检查版本、候选和配对关系。

环境和计数器名称内部的空白具有语义，例如 `panel` 与 ` panel ` 可以分别声明。导航、引用与重命名不会把它们合并，普通名称的重命名保留含空白的其他名称。含空白的名称暂不进入静态符号索引，也不提供精确编译诊断或拼写修复；参数外的排版空白不受影响。逐字环境只按其实际名称识别，不将 ` verbatim ` 当成 `verbatim`。

普通标签引用也按完整键名匹配，`label{plain}` 与 `label{ plain }` 属于不同的标签。导航、引用、重复定义诊断及重命名不会合并含空白的其他标签；含空白的标签暂不进入静态符号索引。`cref` / `Cref` 的键列表继续按列表规则处理，重命名保留逗号及各键之间的空白，未定义引用诊断也按调用类型核对键名。

`refcount` 的 `getrefnumber` / `getpagerefnumber`、`getrefbykeydefault`、`IfRefUndefinedExpandable` / `IfRefUndefinedBabel` 和 `refused` 支持标签补全、导航、悬停、引用及重命名，并提供命令片段与参数提示。只将首个参数作为标签，保留字段名、默认值和条件分支；不会将同一行其他引用的编译警告归到不产生警告的读取或条件判断命令上。

natbib 的 `citealt` / `citealp`、`citenum`、`citeyearpar`、`citefullauthor` 及 `Citet` / `Citep` / `Citealt` / `Citealp` / `Citeauthor` 支持文献键补全、导航、引用、语义高亮、安全重命名、编译警告定位及拼写修复，并提供命令片段与参数提示。识别支持的星号形式及星号前后的空白和注释，保留引用列表、注释参数和正文。

biblatex 的 `fullcite` / `footfullcite` 与普通引用共用文献键导航、补全、引用查找、重命名及编译警告定位，并提供命令片段与参数提示。重命名保留前后注释、可选说明及引用列表中的其他键；这两个命令不支持的星号调用不会被当作文献键引用。

引用命令最多识别两个可选说明参数；出现多余说明时，后面的正文不会参与文献键补全、导航、重命名或精确编译警告定位。说明参数按 TeX 规则在首个未受花括号保护的 `]` 处结束；文字中的 `[`、受花括号保护的方括号、空白和注释仍会保留，参数提示也遵循相同边界。

`defcitealias{键}{显示文字}` 的单个静态键参与上述编辑功能，`citetalias` / `citepalias` 与普通引用使用同一文献键；重命名同步维护别名设置与引用，保留显示文字。别名设置本身不产生缺失文献键警告，不会领取同一行其他引用的编译诊断；逗号列表、含语义空白或动态的别名键不作推断。

`setcounterref` / `addtocounterref`、`setcounterpageref` / `addtocounterpageref` 分别识别首个计数器参数和第二个标签参数，提供各自的补全、导航、引用、重命名、编译诊断和拼写修复。同名计数器与标签仍属于不同的符号，修复和重命名只改动相应参数；支持命令片段、参数提示及跨行标签的补全。常用的带星号引用（如 `ref*`、`pageref*`）也支持名称补全和参数提示。

`Ref` 与 `autopageref` 的标签及星号形式也支持上述编辑功能，识别星号前的空白或注释。不带星号时可能同时产生普通引用与超链接引用警告，诊断和拼写修复分别核对调用；不会把超链接警告归给只产生普通警告的星号调用或不产生警告的读取命令。

选择单标签引用、环境或计数器名称补全时，以候选的完整名称替换当前名称参数，包括旧名称内部的首尾空白，避免补全后仍引用另一个名称。保留参数分隔符、数值、格式和参数外的排版；跨行名称使用当前行的主编辑与互不重叠的附加删除编辑，符合 LSP 对补全编辑的单行要求。动态名称与无法安全安放主编辑的空行不提供建议。

精确定位的未定义计数器提供内置计数器、当前项目的 `newcounter` / `newaliascnt` 和拥有计数器的定理的拼写建议，例如将 `setcounter{equatoin}{2}` 的名称改为 `equation`，保留数值、参数外的空白和其他调用。计数器名称内部的空白具有语义，不作去空白匹配；此类诊断保留整行位置。无编号或共享编号的定理不作为独立计数器候选；已有同名声明、候选定义有歧义、诊断过期或当前实参不再匹配时拒绝修复，兼容旧客户端。

跨文件重复定义会标出每处键名，并提供可跳转的关联定义；编辑、关闭缓冲区、磁盘文件变化或项目依赖调整时同步刷新其他打开文件的诊断。独立论文之间的同名键互不冲突，共享定义会汇总实际使用项目中的冲突。该检查无需编译，按静态依赖分析；不尝试展开宏或模拟 TeX 条件分支。

跳转、悬浮、补全、参数提示和重命名会使用已保存主文档的依赖关系区分独立论文，避免其他项目的同名标签、文献、宏或环境干扰。共享定义的引用查询和重命名会覆盖所有使用它的项目，重命名也会检查这些项目中的冲突；共享源码中的引用如果在不同项目里指向不同定义，或缺少对应定义，则拒绝重命名。尚未关联到已保存主文档的缓冲区继续使用工作区范围。

共享源码中的输入文件和图片路径也按各主文档分别解析，编译输入检查使用当前编译的上下文。根不唯一且同一参数指向不同文件时，不提供单一跳转；路径补全可搜索这些主文档目录。文件移动要求所有使用者的路径编辑一致，一致时合并为一次编辑；存在冲突或某个项目无法解析该路径时拒绝改写。

文件路径补全会同时查找主文档目录和当前文档目录，优先选择编译主文档目录，与 TeX 读取同名文件时保持一致，支持相对父目录和子目录；按加载命令处理扩展名，保留文献列表中的其他项，以及目录后已有的斜杠。`\url` / `\href` 的 URL 参数独立解析，允许 `%20` 等编码，不把 URL 中的文本当成 LaTeX 命令。

单文件参数中的逗号属于路径：`\includegraphics{images,one/plot,one.pdf}`、`\include{chapter,one}`、`\subfile{chapter,one}` 和 `\addbibresource{refs,one.bib}` 在逗号后继续补全完整文件名。`\bibliography`、`\usepackage` 和 `\includeonly` 等列表参数仍只补全当前条目，保留其他名称与分隔符。

`\includegraphics` 还会搜索当前项目中 `\graphicspath{{figures/}{plots/}}` 声明的目录，支持图片跳转、子目录补全和文件重命名。移动图片目录或主文档时会同步更新目录声明，并尽量保留图片的简短名称和省略的扩展名。路径以当前编译主文档目录为基准，共享包里的声明也遵守这一规则。允许空格和中文，识别以 `/` 结尾的静态目录；移动主文档时也会重算尚不存在的目录。如果共享声明在不同项目中需要不同的替换路径，会拒绝该次文件移动编辑。不展开宏，也不模拟条件、局部作用域或多次声明的覆盖顺序。

图片省略扩展名时，按默认扩展名顺序逐个搜索编译根目录及声明目录；支持的显式扩展名先按原名查找。例如根目录有 `plot.png`、`figures/` 有 `plot.pdf` 时，`\includegraphics{plot}` 选中 PDF，显式 `plot.png` 选中 PNG。子文件所在目录不会提前覆盖这些图片；以子文件自身为根时才使用它的目录。跳转、补全、输入跟踪及文件重命名共用这一搜索基准。

图片重命名会检查整批文件移动后的搜索结果，保留仍指向原图片的简写；简写将选中其他图片时，改用相对于新编译根目录的路径和实际扩展名。同批移动其他文件造成的同名遮蔽也会触发引用更新；无法安全保持目标时拒绝编辑，避免编译成功却使用了另一张图片。

`\includeonly{chapter-a, chapter-b}` 支持列表路径补全、跳转和文件/目录重命名，保留其他列表项与空白；重命名选中章节时同步维护编译选择。该命令只选择 `\include` 已声明的章节，不会单独建立输入依赖。

`\input` 可补全上述 TeX 来源类型，省略 `.tex` 时保留常见简写，其他扩展名会显式写入；跳转也遵守仅自动推断 `.tex` 的规则。主文档可以使用 `.tex` 或 `.ltx` 扩展名。 输入路径遵循 TeX 的默认扩展名搜索顺序，例如 `chapter.ltx` 和 `chapter.ltx.tex` 并存时优先后者。 `\include` 和选章列表按 LaTeX 规则补 `.tex`，不会误指向同名无扩展文件或 `.ltx` 文件；例如 `\include{chapter.ltx}` 对应 `chapter.ltx.tex`。

输入文件重命名也会核对整批移动后的 `\input` 目标，包括同批移入和移走的文件。新根目录中的同名来源遮蔽原来的文档相对回退路径时，使用明确的根相对路径；改成 `.ltx` 等扩展名后仍会优先读入同名 `.ltx.tex`，无法通过路径保持目标时拒绝编辑。裸文件名、引号路径、空格和中文路径遵守相同检查。

`\bibliography` 和 `\bibliographystyle` 分别补 `.bib` 和 `.bst`，已有相同后缀时保留；例如 `\bibliography{refs.ltx}` 读取 `refs.ltx.bib`，不会读取同名的 `refs.ltx`。文献库通过 `\bibliography` 使用时，改名必须保留 `.bib` 后缀。`\addbibresource` 继续使用显式资源路径。

LaTeX 在写出 `\bibliography` 的数据库名称前会移除空格、制表符和换行，因此 `\bibliography{my refs}` 实际读取 `myrefs.bib`；目录和扩展名中的空白也按这一规则处理。导航、依赖和重命名会选择实际读取的文件，忽略带空格的同名干扰文件。`\addbibresource` 的显式文件名继续保留空白。

`\bibliographystyle` 会保留名称中的空白，而 BibTeX 会拒绝这样的辅助文件指令，包括名称首尾的空白。服务器不将它解析成可加载样式，补全会排除无法表示的文件名，重命名也会拒绝引入这类路径；编译仍报告工具产生的错误。

宏包和文档类参数是加载名称，`\usepackage` / `\RequirePackage` 总是追加 `.sty`，`\documentclass` / `\LoadClass` 总是追加 `.cls`；例如 `\usepackage{local.sty}` 查找 `local.sty.sty`。补全和重命名会去掉目标文件最后一个由加载器追加的后缀，避免重复扩展名；跳转与依赖跟踪遵循相同规则，并跳过同名的无扩展名文件。文件移动也会检查这些引用在整批移动后仍选中预期目标。

`\RequirePackageWithOptions` / `\LoadClassWithOptions` 沿用相同的查找规则，支持本地文件依赖、补全、跳转、缺失文件修复和文件重命名；前者也识别包列表。命令和签名补全包含 `\RequirePackage`、`\LoadClass` 及这两个转发命令。普通加载器接受 `[options]{name}[minimum version]`，转发命令接受 `{name}[minimum version]`，并由 LaTeX 转发当前包/类的选项；服务器不会在转发命令前错误地建议显式选项参数。

`\PassOptionsToPackage{options}{name}` / `\PassOptionsToClass{options}{name}` 的第二个参数支持本地文件补全、跳转和安全重命名。移动宏包或文档类时，同步更新选项转发声明与实际加载命令，保留选项内容、注释和换行，避免编译仍成功但选项失效。单独转发选项不会把文件加入静态输入依赖；这些名称按选项表键处理，含内部或首尾空白、宏展开及未能解析的目标不作路径推断。命令片段和参数提示包含两个必选参数。

LaTeX 会忽略宏包和文档类加载名称中的空格、制表符和换行，例如 `\usepackage{my local}` 加载 `mylocal.sty`。查找、补全、诊断和重命名遵守相同规则；不会将带空格的同名磁盘文件当成这个名称实际加载的来源，也不会为其生成不安全的路径更新。

路径补全会按加载规则匹配已经输入的空白，支持跨行的宏包、文档类和 `\bibliography` 名称，包括目录片段；接受补全后仍能跳转到编译器实际读取的文件。无法用于这些加载器的带空格目录不会出现在候选中，`\input` 和 `\addbibresource` 继续保留可用的空格路径。`\bibliographystyle` 参数已有空白时，不提供会留下无效空白的路径补全。

## 构建与运行

安装当前稳定版 Rust，然后执行：

```sh
cargo build --release --locked
./target/release/latex-lsp --stdio
```

服务器收到 `shutdown`、`exit`，或 stdio 输入流关闭时，会取消并回收编译与 SyncTeX 进程组，避免编辑器断开后遗留外部工具。未先完成 `shutdown` 就发送 `exit` 时，仍按 LSP 返回退出码 `1`。

进程从标准输入读取 LSP 消息，并向标准输出写入带 `Content-Length` 的 JSON-RPC 消息；通常由编辑器启动。直接运行时等待输入属于正常行为。也可以安装到 Cargo 的可执行文件目录：

```sh
cargo install --path . --locked
latex-lsp --version
```

### Neovim 0.11+

确保 `latex-lsp` 在 `PATH` 中，在配置里添加：

```lua
vim.lsp.config('latex_lsp', {
  cmd = { 'latex-lsp', '--stdio' },
  filetypes = { 'tex', 'plaintex', 'bib', 'bst' },
  root_markers = { '.latexmkrc', 'latexmkrc', '.git' },
  capabilities = { workspace = { diagnostic = { refreshSupport = true } } },
  handlers = {
    ['workspace/diagnostic/refresh'] = function(err, result, ctx, config)
      local response = vim.lsp.handlers['workspace/diagnostic/refresh'](err, result, ctx, config)
      local client = vim.lsp.get_client_by_id(ctx.client_id)
      if not err and client and client:supports_method('workspace/diagnostic') then
        for bufnr in pairs(client.attached_buffers) do
          client:request('textDocument/diagnostic', {
            textDocument = { uri = vim.uri_from_bufnr(bufnr) },
            identifier = client.server_capabilities.diagnosticProvider.identifier,
          }, nil, bufnr)
        end
      end
      return response
    end,
  },
})
vim.lsp.enable('latex_lsp')
```

上面的能力声明启用服务器主动刷新诊断，处理器同时更新工作区和已打开的文档。Neovim 0.12.6 默认未声明 `refreshSupport`，其默认处理器在启用工作区拉取后还会跳过已按文档拉取的缓冲区；这段配置保证编译完成和跨文件修改后，当前文件也显示最新诊断。

打开 `.tex` 后，可用 `vim.lsp.buf.hover()` 查看提示，`vim.lsp.buf.definition()` 跳转，`vim.lsp.buf.references()` 查找引用，`vim.lsp.buf.rename()` 跨文件重命名。补全可通过 `<C-x><C-o>` 或支持 Neovim LSP 的补全插件触发；snippet 需要客户端声明支持。

输入命令参数时，可通过 `vim.lsp.buf.signature_help()` 查看签名；支持自动参数提示的插件也可使用标准 `textDocument/signatureHelp`。

自动提示的触发字符包括 `{`、`[`、`<`、`(`、`|`、`*`、`+` 和逗号，并在常见结束分隔符处更新当前参数。其他自定义分隔符可手动请求提示。

环境参数提示支持 `\newenvironment`、`\NewEnviron` 和 xparse 的 `\NewDocumentEnvironment` 系列定义，以及 `tabular`、`minipage`、`figure` 等常用环境；`\newtheorem` 定理提示可选标题 `[note]`。通过 `\begin{panel}` 或直接调用 `\panel` 均可查看参数，自定义环境的直接命令补全会插入必选参数的占位符并保留可选参数默认值。自定义命令与环境识别常规参数数量/默认值，以及 xparse 的 `m`、`o`、`O`、`s`、`t` 及 `d/D/r/R` 参数；不支持的参数规格和存在多个定义的名称不推断签名。 etoolbox 的 `newrobustcmd` / `renewrobustcmd` / `providerobustcmd` 也支持导航、符号、补全、参数提示和跨文件重命名，识别带星号、无花括号及经 `expandafter` 展开的字面 `csname` 声明；补全保留首个可选参数的默认值。

计数器操作支持命令片段、参数提示和名称补全，包括 `setcounter` / `addtocounter`、`stepcounter` / `refstepcounter`、`value` / `arabic` 等格式化命令、`counterwithin` / `counterwithout` / `numberwithin`。名称候选来自内置计数器、当前项目的 `newcounter` / `newaliascnt` 和拥有计数器的定理声明；支持新计数器、别名及定理的共享/重置参数，保留已有名称后缀、空白和其他实参。不同论文之间的候选按依赖隔离，宏生成的名称不作推断。

静态 `newcounter` / `newaliascnt` 声明支持跳转、悬停、引用、文档/工作区符号及跨文件重命名。重命名联动维护计数器操作、子计数器重置、定理共享编号、别名和格式化命令，包括字面 `csname`、`aliascntresetthe` 及别名元数据；同名的独立宏和 cleveref 的显示文字保持原样。名称冲突、共享引用在其他论文中指向独立声明、或同名定理与计数器对格式化命令的所有权有歧义时拒绝改动。

`newlength`、`newsavebox`、`newcount` / `newdimen` / `newskip` / `newmuskip` / `newtoks` / `newbox` 等寄存器分配，以及 `chardef` / `mathchardef`、寄存器绑定和字体声明也进入符号索引，支持变量补全、导航、悬停和跨文件安全重命名；识别直接名称和经 `expandafter` 展开的字面 `csname` 声明。常用长度操作、保存盒命令提供片段及参数提示；重命名会检查已有宏、寄存器、计数器派生命令和常用内置长度/寄存器原语的冲突。

fontspec 的 `newfontfamily` / `renewfontfamily` / `providefontfamily` / `setfontfamily` 和对应的 `fontface` 声明也支持命令补全、导航、悬停、引用及跨文件安全重命名。识别裸命令与花括号包裹的命令目标；声明提供片段和参数提示，区分字体名前后的可选特性，生成的字体切换命令按零参数处理。沿用项目隔离、冲突与歧义检查，保留字体名称、特性、注释和逐字文本，不展开动态声明。

LaTeX 标准的 `DeclareTextFontCommand`、`DeclareMathAlphabet`、`DeclareSymbolFontAlphabet` 也进入命令索引，生成的命令按单个正文参数提供提示及补全。`DeclareFixedFont` 和以命令为目标的 `DeclareMathSymbol` 作为零参数字体选择器或符号常量进入变量索引；字符目标不会误记为命令声明。五种声明均提供命令片段、字段参数提示及跨文件安全重命名，保留编码、字体族、字形、字号、数学类别和字符槽位。

`DeclareMathAccent`、`DeclareMathRadical` 和以命令为目标的 `DeclareMathDelimiter` 也进入索引，支持导航、引用、语义高亮和跨文件安全重命名，并提供声明片段及字段参数提示。重音和根号命令按一个必选参数提供调用提示；根号不推断可选次数。定界符是零参数符号，可直接使用或跟随 `left` / `right` 伸缩；字符目标不会误记为命令声明。重命名保留数学类别、大小字体及槽位，不改动注释和逐字文本。

常用标准数学重音和定界符（如 `hat`、`widehat`、`vec`、`langle` 和 `Vert`）提供补全、悬浮说明和命令拼写修复候选。重音、上下划线和 `sqrtsign` 按一个表达式参数提示及补全，定界符不追加参数；命令和环境重命名也会检查这些内置名称，避免覆盖已有数学命令。

标准希腊字母及其变体、大小写形式和常用算子（如 `epsilon`、`varepsilon`、`Gamma`、`sin`、`log`）也提供补全、悬浮说明、拼写候选及重命名冲突保护。字母和算子不追加调用参数；amsmath 的 `operatorname` / `operatorname*` 和 `DeclareMathOperator` / `DeclareMathOperator*` 提供正文、命令目标等字段提示，兼容裸命令目标、注释和跨行星号。

mathtools 的 `DeclarePairedDelimiter` / `DeclarePairedDelimiterX` / `DeclarePairedDelimiterXPP` 声明同样支持导航、引用、悬停、符号及跨文件重命名。参数提示识别星号自动缩放与 `[size]` 手动尺寸，X/XPP 的字面参数数量限于 1–9；补全只插入正文必选参数，保留其实际参数编号。声明本身提供命令片段及参数提示，X/XPP 的方括号参数数量为必填项；动态数量或定义有歧义时不推断调用签名，已有调用参数和声明的定界符、前后代码保持原样。

直接 `\newif\ifdraft` 和字面 `\expandafter\newif\csname ifdraft\endcsname` 声明提供布尔符号、跳转、悬停和项目内的派生命令补全。从 `\ifdraft`、`\drafttrue`、`\draftfalse` 或对应字面 `csname` 引用发起重命名时，输入新的基础名称（例如 `release`），同步维护三种命令及声明；保留同名的独立 `\draft` 宏。只经字面 `csname` 使用的名称支持连字符和中文；存在直接控制序列时，新名称必须能组成 TeX 命令，不提供无法直接键入的补全。新名称与宏、寄存器、环境、其他开关或内置条件原语冲突，以及共享文件在其他项目中指向独立开关时拒绝修改；不展开动态声明。

ifthen 的 `newboolean` / `provideboolean` 与 etoolbox 的 `newbool` / `providebool` 复用同一布尔索引；重命名同时维护 `boolean`、`setboolean`、`setbool`、`booltrue` / `boolfalse`、`ifbool` / `notbool` 中的名称参数，以及直接或字面派生命令。名称和值参数提供补全、片段及参数提示，保留后缀、空白与其他实参；只读条件支持内置 `true` / `false`，赋值命令只建议已声明的开关。`ifboolexpr` / `ifboolexpe` 和 `whileboolexpr` / `unlessboolexpr` 支持静态 `bool {名称}` 操作数的补全、导航、引用和重命名，包括嵌套逻辑与未闭合表达式中的补全；跳过 `test {...}` 的普通文本及动态名称，不展开宏。

etoolbox 的静态 `csdef` / `csgdef` / `csedef` / `csxdef` 声明进入宏索引，支持导航、符号、参数提示、补全和跨文件重命名，维护直接调用、`csuse` 及字面 `csname` 引用。识别连续的 `#1#2...` 参数和仅通过名称调用的中文或带连字符名称；不展开动态名称，不推断复杂分隔参数，不模拟局部作用域或重复定义的覆盖顺序。

仅通过静态名称声明和调用的宏可以重命名为中文、连字符或数字名称，例如 `发布-模式`；同样适用于经 `expandafter` 展开的字面 `csname` 声明。任一使用该定义的项目中存在直接声明或直接调用时，新名称仍须仅包含 ASCII 字母或 `@`，避免破坏 TeX 控制序列。重命名保留普通字符串、注释和逐字文本，并检查内置原语与现有定义的冲突。

宏和环境的重命名会保护 TeX/e-TeX 的核心原语，包括输入输出、字符类别与字符码、盒子、自动执行 token 列表及表达式运算，例如 `write`、`catcode`、`shipout`、`numexpr`。这些名称也用于静态名称补全和命令拼写建议；保留已有的引擎专用原语保护。

etoolbox 的 `csuse` / `csmeaning`、`ifcsdef` / `ifcsundef` / `ifcsvoid`、宏类型检测及名称比较命令中的静态控制序列名称支持补全、导航、引用与重命名；识别 `ifcsequal` / `ifcsstrequal` 的两个名称参数，保留 `ifcsstring` 的字符串和条件分支正文。派生的环境、计数器和布尔命令仍归属于原始声明。`csuse` 调用可显示被调用命令或环境的参数提示，包括可选参数默认值；动态名称不作推断。

这些命名接口的名称参数按原样匹配；首尾空白属于命令名，含空白的名称不会归并到普通控制词。选择已知名称补全时替换整个名称参数，跨行空白通过额外编辑移除，保留后续参数。

单名称接口的名称参数仅包含一个普通宏时，例如 `\csuse{\keyname}`，编译器报告的未定义宏可精确定位并提供版本化拼写修复；适用于单名称声明、读取、修改和条件检测接口。`\csuse\keyname` 等单个裸控制词参数同样适用，修复保留裸写法及后续实参和正文。`cslet` 同时核对已读取的来源命令；混合名称和用户宏包装继续保留整行诊断。

`ifcsequal`、`ifcsstrequal` 的两个名称参数，以及 `csletcs`、`letcs` 的来源名称也支持上述诊断与修复。要求仅一个名称参数是直接宏，其余名称参数为静态字面值；核对完整调用的源码回显，保留复制目标和条件分支。`letcs` 的目标控制词不会被误当成名称展开错误；多个动态名称、重复宏参数及 `csletcs` 目标名称的复杂展开继续使用整行诊断。

命名宏修改接口 `csappto` / `cspreto` 及其展开、全局变体（`cseappto`、`csgappto`、`csxappto`、`csepreto`、`csgpreto`、`csxpreto`），以及 `csundef` / `csgundef` 也支持片段、参数提示、名称补全、导航和跨文件重命名。只将名称参数关联到原始声明，保留追加或前插代码中的普通文本，并独立识别其中的宏调用；不将修改操作推断为新的声明。

`cslet`、`letcs`、`csletcs` 的静态别名声明区分目标与来源：别名有独立的符号、导航和重命名，来源参数关联原宏；重命名原宏会维护这些引用。支持有花括号和无花括号的控制序列参数、名称补全、片段与声明参数提示。纯名称别名可改为中文名称；动态目标不会把来源误记为声明，不展开动态名称，也不根据来源推断别名调用的参数签名或模拟后续重新赋值。

`\expandafter\letcs\csname alias\endcsname{source}` 同时识别字面别名目标和展开后的来源名称，支持名称补全、参数提示、跨文件与共享项目重命名，以及环境、计数器、开关等派生命令作为来源的情况。只有相邻的显式 `expandafter` 和完整静态 `csname` 才沿用此规则；动态目标不推断来源参数的位置。

etoolbox 的 `newtoggle` / `providetoggle` 使用独立命名空间，支持 `settoggle`、`toggletrue` / `togglefalse`、`iftoggle` / `nottoggle` 和上述表达式中的 `togl {名称}` 操作数。提供名称和值补全、片段、参数提示、布尔符号、跨文件导航与安全重命名；同名 boolean 保持独立。重命名同时维护直接或字面的内部 `etb@tgl@名称` 控制序列，并检查生成命令冲突。

在语法错误处调用 `vim.lsp.buf.code_action()` 可选择快速修复；`vim.lsp.buf.document_highlight()` 高亮当前符号的定义和引用。Neovim 0.12 中可用 `vim.lsp.buf.selection_range(1)` 扩大语法选择范围。

其他编辑器可将 `latex-lsp --stdio` 配置为 `tex` / `latex` / `bib` / `bst` 文件的语言服务器。建议将根目录设为当前 LaTeX 项目，避免把多个无关项目混在同一个工作区。

## 编译

编辑功能不依赖 TeX；编译需要相应工具在语言服务器的 `PATH` 中。默认使用 `latexmk` 和 pdfLaTeX，把输出写入根文档旁的 `build/latex-lsp/`。编译前先保存项目文件，服务器会拒绝编译含未保存内容的依赖，避免诊断与编辑器内容不一致。

`listings` 等工具实际读取的代码文件也参与编译依赖校验，包括 Rust、Python、C/C++、Java、JavaScript/TypeScript、Go、Shell、C#、Lua、R、Julia、Kotlin、Swift、Scala、SQL、Fortran 和常见 Web 文件后缀，以及 `.toml`、`.ini`、`.cfg`、`.conf`、`.md`、`.rst` 配置或文档。只采纳 recorder 确认的读取，不因目录中存在这些文件就导入依赖。代码中的 `\label` 等文字不会成为 LaTeX 符号；显式 `\input{definitions.rs}` 等源码包含仍正常支持导航和重命名。代码内容即使保持大小与修改时间不变，也会使旧 PDF 和 SyncTeX 失效，需要重新编译。

通过 `workspace/executeCommand` 调用以下命令，第一个参数为当前文档 URI（也可使用 `{ "uri": "file:///..." }`）：

- `latex.build`：立即返回 `{status: "started", buildId, rootUri}`，编译在后台运行。同一根文件已有任务时返回 `running` 和原任务 ID。
- `latex.rebuild`：强制重新编译；默认 latexmk 增加 `-g`，直接 TeX 引擎和 Tectonic 每次直接运行。用于恢复被修改的产物或需要跳过 latexmk 增量判断的情况。同一根文件正在编译时，将重复请求合并为一次后续强制编译，即使 `onSave` 为 `false` 也会执行；保存事件保留已排队的强制请求，后续任务使用最新配置和已保存内容。取消、相关文件事件和关闭服务器会清除队列。
- `latex.cancelBuild`：取消该文档对应的编译；省略参数时取消全部编译。Unix 上同时终止 latexmk 启动的子进程。
- `latex.buildStatus`：查询当前任务或最近一次编译结果，未编译时返回 `idle`；运行中的 `queued` 表示是否还有后续编译，`queuedRebuild` 表示后续任务是否为强制编译。启动响应、运行状态及开始/完成通知的 `rebuild` 表示当前任务是否为强制编译。

任务在编译工作线程启动前已被取消时，不会调用编译器、创建输出目录或替换旧日志，已有 PDF、日志和辅助文件会保留。取消结果不把这些旧文件作为本次编译产物返回。

服务器发出 `latex/buildStarted` 和 `latex/buildFinished` 通知，两者都包含实际 `executable` 和可推断的 `engine`（使用自定义参数或无法识别的工具时为 `null`）。完成通知还包含 `status`（`success` / `error` / `cancelled` / `timeout`）、`buildId`、`rootUri`、`pdfUri`、`logUri`、`exitCode`、`diagnosticsCount`、`errorsCount`、`warningsCount`、`dependenciesCount`（包含根文件的来源数量）、`durationMs`、`message` 和有长度限制的 `output` 摘要。成功结果的 `pages` 为最终 TeX 日志报告的页数（未知时为 `null`），`pdfSize` 为实际 PDF 的字节数；失败结果两者为 `null`。`latex.buildStatus` 保留相同摘要。若文档或已知输入选择在编译中变化，`stale` 为 `true`，不会发布这次编译的旧诊断，并清除该项目上一次编译的诊断，避免旧错误继续留在编辑器中。失败编译不把可能不完整的 PDF 标记为成功结果。

编译管道输出超过 4 MiB、日志超过 8 MiB 时，分析缓冲区保留开头和结尾，省略中间部分；完整日志仍保留在磁盘。省略后清除文件栈，显式文件位置和新出现的文件上下文仍可定位，其他诊断回退到主文档。完成通知的 `diagnosticsTruncated` 标明 TeX 或文献诊断使用了省略后的内容，此时诊断数量仅统计已分析部分。部分 recorder 或文献依赖列表不会替换上一次完整记录。

PDF、`.fls` recorder 和 `.blg` 文献日志的更新检测同时比较内容指纹与文件元数据。编译工具保留输出大小和修改时间时，实际改写的 PDF 仍能确认为新产物，新的 recorder 输入及文献警告也会正常读取；这适用于保留时间戳的文件复制或自定义编译驱动。

工具返回成功但没有更新 PDF 时，服务器会检查已知输入的修改时间：来源比旧 PDF 新或已被删除则报告产物过期，并保留磁盘上的旧 PDF；产物仍有效的无操作编译可以成功。有 recorder 记录时优先按记录检查，并保留文献来源检查；未被记录的选章外文件不会导致过期产物误报。部分 TeX 版本也记录选章外文件的存在性检查，这些文件仍会保守参与检查。图片也参与编译期间变更、过期 PDF 和 SyncTeX 检查；二进制内容不进入文本索引。不生成 recorder 的工具使用当前能静态解析的图片路径。

服务器还保留已生成 PDF 的内容指纹。PDF 被外部工具或失败编译覆盖后，即使大小和修改时间未变，SyncTeX 与后续不重写 PDF 的编译也会要求重新编译；只调整修改时间、内容不变的 PDF 仍有效。成功的无操作编译保留旧 PDF 实际对应的输入范围，不会因本次 recorder 改变而遗忘旧来源。真正生成新 PDF 后才更新这项历史。

PDF 的历史同时记录 `.synctex.gz`、`.synctex` 的内容及缺失状态。映射被覆盖、删除或另一格式的映射后来出现时，双向查询要求重新编译；保留大小与修改时间的替换也能识别，内容未变的时间戳调整仍可查询。映射单独变化时，有效 PDF 的无操作编译仍可成功，查询继续等待生成新 PDF 与映射；失败编译和无操作编译不会接纳被替换的映射。

客户端声明 `window.workDoneProgress` 时，服务器还通过标准 `$/progress` 显示编译开始和完成，可通过编辑器的取消按钮中止编译。客户端拒绝或不响应进度创建请求时，编译仍会继续。

开启 `onSave` 后，编译期间的多次保存会合并为一次后续编译，重新读取最新保存内容。取消编译或关闭服务器会同时清除排队任务。若开始后续编译时仍有未保存的依赖，会跳过该次编译并记录原因。

latexmk 和直接 TeX 引擎编译前会为静态 `\include{chapters/name}` 预建输出目录中的 `.aux` 子目录，包含由 `\input` 间接载入的章节声明，也识别静态命名调用与纯别名产生的 `include`，支持本地宏包、嵌套输入和路径周围的注释。目录创建仅处理输出目录内的相对静态路径，跳过宏、父目录路径、注释和逐字文本。

编译前会重新遍历已保存文件中的依赖，包含本地 `.sty`、`.cls` 及其输入文件；子文件路径也会尝试相对于主文档目录解析。这样，磁盘上的子文件新增依赖或本地包在编译期间变化时，也会参与保存检查和过期结果检查。

编译后读取本次更新的 `.fls` recorder，发现 TeX 宏展开后实际读取的 `.tex`、`.ltx`、`.sty`、`.cls`、`.def`、`.clo` 和 `.bib` 文件，以及 PDF、PNG、JPEG、EPS、SVG 图片。项目目录内的来源会进入索引，参与之后的根文件识别、保存编译和未保存检查；系统 TeX 包不会批量进入索引。首次发现的来源已有未保存内容或在编译期间发生磁盘变化时，本次诊断也会被丢弃，无关的未保存缓冲区不受影响。上次记录的依赖会保守保留到新的 recorder 替换，因此刚移除的依赖可能仍需先保存。默认 latexmk 和 TeX 引擎参数启用 recorder；自定义参数需自行启用 `-recorder`，不生成 `.fls` 的工具仍使用静态依赖。

recorder 确认读取的图片即使位于工作区和根文档目录之外，也会作为二进制依赖保留，参与后续编译的变更检查、文件通知取消、诊断刷新及 PDF / SyncTeX 内容历史校验。共享目录中的图片、宏展开后读取的外部图片都遵守相同规则；等长替换并保留修改时间也能识别。

recorder 同时保留 TeX 实际打开的路径及其物理文件绑定。符号链接切换目标或被删除后，即使原目标未变、新目标早于 PDF，也会拒绝旧 PDF 和 SyncTeX；未重写 PDF 的编译不会覆盖原有绑定历史。编译期间切换已知链接会取消任务或丢弃诊断；新写出的 PDF 若读入目标无法确认，需要重新编译。已知路径的新外部目标即使未进入源码索引，也会保存内容快照，参与编译期间变化和旧 PDF/SyncTeX 检查。新 recorder 不再读取的链接不会继续影响新 PDF，文件移动则同步更新当前依赖，保留旧产物历史供校验。

BibTeX/Biber 日志确认读取的 `.bib` 和 `.bst` 也保留原始路径绑定，遵守相同的链接切换、删除、通知取消和旧产物检查。TeX recorder 与文献日志分别更新各自依赖，截断的文献日志不会替换完整历史。仅重跑 TeX 并重用旧 `.bbl` 时，不会把改变后的文献链接或文件内容当成本次文献来源；即使保留原文件大小与修改时间，也需要实际重跑文献工具。新日志仍列出的已知路径即使已被删除、或切换到未索引的外部文件，也保留变化检查；新完整日志移除的文献依赖不会继续使新 PDF 失效，目录与文件改名同步维护文献绑定。

默认输出目录使用 `build/latex-lsp`，默认 latexmk 参数让 BibTeX 保持在主文档目录运行，以正确处理 `../library.bib` 等相对路径。显式配置隐藏目录、绝对路径或包含 `..` 的输出目录时，会保留 latexmk 切换目录运行 BibTeX 的方式，以适应 BibTeX 的文件写入限制；这类配置中，父目录文献路径可能需要额外的工具配置。

本地 `.bst` 样式通过 `bibliographystyle` 参与路径补全、跳转、文件移动及编译输入检查；修改时需要先保存，编译期间变化会使结果过期。BibTeX 报告的样式错误会定位到 `.bst` 对应行；编辑时不把它作为 LaTeX 语法解析。

BibTeX 带行号的文献库及样式错误按日志中的输入名称识别类型，再定位到符号链接的实际文件；目标使用无关扩展名时仍保留正确行号。辅助文件不会因链接目标带有源码扩展名而被误当成文献来源；路径缺失或实际为目录时，诊断保留在主文件。

Biber 消息中的文献路径按完整文件名边界匹配，`refs.bib.backup`、`refs.bib2` 或目录名中的 `.bib` 不会借用已有 `refs.bib` 的位置。显式的 `in file refs.bib` 和 `in file 'refs.bib'` 优先于错误正文中的文件名；普通文本 `in parser` 不会阻止识别后面的真实来源。引号内的 `in 'wrong.bib'` 或 `file 'wrong.bib'` 不会覆盖显式来源；无法确认的来源保留原错误信息并在主文件显示。

没有显式来源字段时，独立引号包围的完整文件名、`refs.bib:` 及括号中的路径仍可定位；不会从更大的引号文本中截取内嵌文件名。未加引号的路径保留撇号、逗号和目录中的 `.bib`，兼容消息标点及 Unicode 空白分隔符。

日志明确指出的带引号文献路径会作为完整名称处理，保留空格、撇号和文件名内部的 `.bib` 片段。`refs.bib':copy.bib` 等文件名中紧接引号的标点也保留为名称的一部分，文件名中的 `line 700` 不会覆盖真实行号；这些完整名称也用于依赖索引、跳转和文献键重命名。条目警告只在指定数据库中定位文献键；指定文件不存在、路径为目录或引号无法确认时，在主文件标记来源未确认，不借用前缀、后缀或其他数据库的位置，也不将其他文件的条目范围套到当前文件。

当引号后的标点和空格也属于文件名（如 `refs.bib': copy.bib`）时，使用文献日志确认的完整数据库名称消除歧义。多个已记录名称同时匹配时优先完整的长名称，再按共同的搜索路径规则查找文件；完整文件缺失时在主文件显示原错误，不借用短文件的位置。文件名中的 `in file`、`entry` 和 `line` 不会被当作日志字段，已记录的短名称也不会截断消息中另一个边界明确的长名称。

诊断没有为文献路径添加引号时，也使用日志确认的完整名称保留空格及文件名内部的引号，支持消息中的成对括号。例如 `refs.bib line 700 copy.bib` 不会截成 `refs.bib`，其中的 `line 700` 也不会覆盖真实行号。显式来源和独立路径均遵守这些规则；完整来源缺失时在主文件显示原错误并标记来源未确认。

显式 `file` / `in file` 来源未列入输入日志时，也可定位包含空格的完整 `.bib` 路径。文件名范围内的 `line`、`entry` 文字和消息中其他引号文件名不会提供错误位置；完整文件缺失或名称使用 `.bib.backup` 等后缀时，保留来源未确认状态。普通说明文字（如 `in parser: ...` 或 `in 'parser'`）不会抢在后续可确认的文件字段之前成为诊断来源。

日志与诊断使用不同路径写法时，也按同一输入识别：支持绝对路径、相对路径、`./` 和指向同一数据库的目录链接，保留符号链接后 `..` 的实际含义。匹配遵守工具工作目录及 `BIBINPUTS` 的顺序，使用日志确认读取的目标；其他目录的同名文件不会冒充该来源。来源缺失或发生切换时保留完整消息并标记来源未确认，不借用干扰文件的文献条目范围。诊断明确指定且真实存在的其他文件，即使未列入输入记录，仍可正常定位。

BibTeX 警告末尾的 `in 键名` 按文献键的原始内容查找，保留键名中的引号；即使键名为 `entry.bib`、且磁盘上存在同名文件，也定位到实际数据库中的条目。Biber 的 `entry '键' in file '路径'` 则分别识别文献键和来源路径；键名中的 `.bib` 不会让同名文件覆盖实际数据库，未闭合的键字段也不会被当成来源路径。显式指定的来源文件仍优先使用。

Biber 的 `entry` / `Entry` 字段支持单、双引号包围，完整保留 `O'Connor2026` 等带撇号的文献键，并按 UTF-16 范围定位。文件名、其他引号内容和 `subentry` 等单词中的同名文字不会被当成条目字段；截断、未闭合的显式键不会借用消息末尾其他条目的位置。

Biber 行号只取来源字段和引号内容之外的完整 `line 整数` 字段，`line 700 refs.bib` 等文件名、引号内的错误内容及 `outline` 等单词不会覆盖真实行号；条目警告也保留键名的精确范围。BibTeX 样式生成的警告即使正文包含 `line 700`，仍按末尾的文献键定位；带源文件和行号的 BibTeX 错误继续使用工具的独立行号格式。

源码、文献数据库和文献样式的解析类型依据输入命令及工具实际读取的路径确定，符号链接目标的扩展名不会改变用途。例如 `refs.bib` 指向 `.payload`、`.tex` 或 `.png` 文件时仍提供文献键补全、跳转及跨文件重命名，`alias.sty` 指向 `.bib` 时仍解析其中的 LaTeX 命令；样式文件不会产生文献条目。打开、编辑、关闭、重新加载和文件移动都会保留已确认的用途，当前静态声明或新工具记录可更新用途，同时保留未保存文本。文献工具发现的外部数据库遵守源码索引范围，静态文献来源即使没有文献日志也参与旧 PDF 的内容校验。

`\input` 支持花括号、裸文件名和双引号文件名，例如 `\input chapter.tex` 与 `\input "my file"`；这些形式都参与补全、跳转、项目依赖和文件重命名。裸文件名以空白结束；改名、补全或快速修复引入空格时自动添加花括号，已有 ASCII 双引号路径则保留。裸文件名或双引号路径改为中文等非 ASCII 名称时，统一转换为花括号形式，确保 pdfLaTeX 与 XeLaTeX 都能读取目标文件。含宏展开、注释拼接或混合引号的文件名留给编译后的 recorder 发现。

静态 `\input` 和 `\subfile` 的文件查找也记录缺失候选、优先后缀候选及选中文件的身份。缺失来源在失败编译期间补回时，即使没有文件通知，也会将错误结果标为过期并清除历史编译诊断；文件创建通知会取消对应任务及队列。已存在的来源被更高优先级的后缀文件遮蔽，或符号链接切换到另一来源时，同样使结果过期，并阻止不重写 PDF 的编译接受旧产物。这项查找追踪不受 `\includeonly` 影响；源码内容仍使用原有保存、内容变化和 recorder 检查。

`\InputIfFileExists{file}{before input}{if missing}` 的静态文件名也支持路径补全、跳转、项目依赖和文件重命名，使用与 `\input` 相同的查找顺序及扩展名规则。文件中的符号可在编译前跨文件导航和重命名；路径编辑保留两个代码参数、注释及空白，允许中文、空格和逗号文件名。命令补全和参数提示说明第二个参数在读取文件前执行，第三个参数只在文件缺失时执行。缺失文件按 LaTeX 的分支继续编译；服务器不模拟分支执行，静态依赖分析不将只检查存在性的 `\IfFileExists` 视为文件输入命令。

`\IfFileExists{file}{if exists}{if missing}` 的文件名支持路径补全、跳转和文件重命名，可检查 TeX 来源、图片、数据文件和无扩展名文件。编辑保留两个分支，查找及整批文件移动检查遵守 TeX 的后缀搜索顺序；重命名不会把文件存在性检查变成文件读取，也不会将被检查文件中的符号加入主文档的静态作用域。命令补全及参数提示区分存在与缺失两个分支。

`\lstinputlisting[options]{file}` 支持代码文件路径补全、文件链接、定义跳转及版本化文件/目录重命名，接受任意后缀和无后缀文件，保留中文、空格、逗号及调用周围的注释。按主文档目录和 LaTeX 的 `.tex` 优先/原名回退规则选择文件，静态依赖分析不把此路径作为 LaTeX 源码导入符号索引。命令片段及参数提示遵循一个可选参数、不接受星号的调用形式。当前静态编辑支持默认搜索和已识别的字面格式选项；`inputpath`、`style`、宏值、未知选项及项目内命令重定义会跳过路径推断，避免修改错误文件。已解析的静态代码路径在首次编译前就作为数据输入捕获内容快照，包含未知后缀、无后缀及指向 `.tex` 的别名；变化会使构建结果、旧 PDF 和 SyncTeX 失效。候选文件的创建及别名变化也参与构建检查。编译后显示的 `.tex` 样例不会把其中的标签、输入命令或 `listings` 设置带入主文档作用域；同一文件在其他项目中被显式 `\input` 读取时仍保留源码用途。无法静态解析的调用继续依靠 recorder 确认的常见输入格式。 编译器确认代码文件缺失时，服务器结合实际读取提示和源码回显，将错误定位到文件名参数，并提供有界拼写修复。修复保留完整后缀、选项、注释和换行，使用版本化编辑并检查 TeX 后缀遮蔽；宏展开、不确定上下文及自定义搜索设置不提供猜测性的修复。

`\verbatiminput{file}` 和 `\verbatiminput*{file}`（`verbatim` 宏包）也支持任意类型文件的路径补全、链接、定义跳转和版本化文件/目录重命名。星号可以与命令之间留空白；此命令没有可选参数。按主文档目录及 `.tex` 优先规则查找，代码文件参与首次构建快照、PDF 内容历史及 SyncTeX 失效检查，其中的 LaTeX 命令不作为项目源码执行或索引。`listings` 的搜索设置与 `verbatiminput` 的重定义检查彼此独立；无法确认查找规则时跳过静态路径推断。宏包输出缺失文件提示时，服务器结合已确认的日志文件上下文和源码字面路径，给出文件名范围内的警告及有界拼写修复，保留编译成功状态。长文件名折行、星号、注释、CRLF 和版本化编辑均受支持；普通缺失辅助文件、动态路径和命令重定义不生成猜测性的路径修复。

`\VerbatimInput[options]{file}`（`fancyvrb`）也支持补全、链接、定义跳转、版本化文件和目录重命名及静态输入跟踪，接受一次可选参数和可留空白的星号。默认查找遵守主文档目录和 `.tex` 优先规则。双引号路径和字面 `\detokenize` 包装内的文件名也可编辑；补全、改名引入空格时自动保留或补充引号，引入非 ASCII 名称时使用 `\detokenize`，以便 pdfLaTeX 与 XeLaTeX 读取。已知的字面格式选项与 `commandchars=none` 可静态分析；可执行代码的 `commandchars`、未知选项、宏值、命令定制和相关重定义会跳过推断，避免将实际执行的内容误当成展示数据。三类代码输入的配置检查彼此独立。 同族的 `\LVerbatimInput`、`\BVerbatimInput` 使用相同的路径、补全、参数提示、重命名、输入跟踪和缺失文件修复规则，保留各自的排版形式。三个命令共用设置及内部定制检查；缩短的错误回显必须在整个命令族中定位到唯一调用。

FancyVerb 缺失文件错误使用诊断代码 `missing-fancyverb-input`，精确标出引号或字面 `\detokenize` 包装内的文件名，保留错误级别和失败编译状态。兼容 pdfLaTeX、XeLaTeX、跨行调用、折行长路径和缩短的源码回显；最多给出 5 个同目录文件名拼写建议。修复保留选项、星号、注释、CRLF 和编辑器版本，引入空格或非 ASCII 名称时补充相应包装，并检查 `.tex` 遮蔽、文件是否已恢复及项目内定制。来源、回显、宏展开或日志完整性无法确认时保留普通错误，不猜测路径替换。 同一文件同时被展示和通过可执行选项读取时，仍参与输入快照检查，并保留 recorder 确认的源码用途及标签跳转；其他纯展示文件继续排除在符号索引之外。无法解析执行路径或定制时，保守保留 recorder 的来源信息。

编译会单独记录这两个条件命令的静态本地路径，包括尚不存在的候选及优先级更高的后缀候选。编译期间文件出现、消失或符号链接改变目标时，即使未收到文件事件，也会将结果标为过期并丢弃诊断；相关创建、删除、目录变更和重命名通知还会取消正在运行及排队的编译，清除已发布的旧诊断。只检查存在性的数据文件不要求保存缓冲区，修改其内容不会改变条件；不会因此新增源码依赖或导入符号。实际由 recorder 识别的来源仍遵守原有依赖规则。 缺失路径位于已存在的目录符号链接下时，也会记录最近现存父目录对应的规范路径；通过物理路径收到文件或目录创建通知时，同样取消相关编译并清除旧诊断。

历史条件或已记录输入的内容变化后，不重写 PDF 的编译会报告产物过期，SyncTeX 也要求重新编译；源码、图片、文献及样式即使保留原有大小和修改时间，也会按内容识别。存在 recorder 信息时，内容历史以确认的实际输入为准，保留文献工具的额外来源，不额外纳入静态排除的章节。首次编译已生成 PDF 但结果过期时，同样保留原始输入的内容与条件保护；连续失败的空操作编译不会覆盖旧 PDF 的依据。对于编译后才确认的已打开动态输入，同时保留编译前的磁盘内容和编辑器版本；不会将未保存的缓冲区内容记作 PDF 已编译的内容，编译期间保存且保留时间戳也能识别。已知作业产物和静态 `\include` 对应的 `.aux` 文件不参与存在性变化检查，避免正常生成输出使编译失效。每个项目最多记录 4096 个候选路径，诊断和 PDF 的输入与条件历史分别最多保留 128 个项目，重启服务器后重新积累；宏展开、系统 TeX 搜索目录中的检查不在此静态追踪范围内。

静态 `bibliography` / `nobibliography` 数据库列表和 `bibliographystyle` 样式也记录本地候选的存在状态与符号链接目标。编译期间文件补回、消失或切换目标时，即使没有文件事件，也会将结果标为过期并丢弃旧诊断；创建、删除和目录变化通知可取消相关编译并清除历史诊断。按真实 `.bib` / `.bst` 后缀、数据库去空白和样式单文件规则匹配路径；动态或不完整列表、项目内重定义的命令不作推断。候选与其他文件条件共用 4096 项上限；始终缺失而未变化的数据库不会单独使预生成 `.bbl` 的编译过期。

本地宏包和文档类也参与相同的条件追踪，涵盖 `usepackage`、`RequirePackage`、`RequirePackageWithOptions`、`documentclass`、`LoadClass` 和 `LoadClassWithOptions`。宏包按完整静态列表去除 TeX 空白，类名按单文件参数保留内部空格与逗号，复用注释和可选参数规则。加载命令总追加 `.sty` / `.cls` 后缀，显式写出后缀也会再追加一次；追踪按此规则使用实际候选文件。动态、不完整或项目内重定义的同类加载命令不作静态推断；仅传递选项的 `PassOptionsToPackage` / `PassOptionsToClass` 不产生加载条件，候选仍共用上述上限。

静态 `includegraphics` 按图片扩展名、编译根目录及项目内静态 `graphicspath` 的搜索规则，保守记录选定图片及之前候选的存在状态和符号链接目标。尚不存在的图片目录同样参与追踪，目录别名保留原路径；编译期间补图会丢弃旧缺图诊断，图片或目录创建通知可取消编译，包括工作区外物理路径的通知。显式扩展名与带点名称的后缀回退共用图片导航规则，不采用子文件目录作为编译工作目录，也不追踪已知编译产物。候选共用 4096 项上限；搜索目录达到 256 项、路径声明动态、不完整或出现多次、项目重定义 `includegraphics` / `graphicspath`，或自定义 `DeclareGraphicsExtensions` / `DeclareGraphicsRule` 时，跳过这项静态图片条件，已确认输入的 recorder 与内容检查继续生效。

文件监听通知 `workspace/didChangeWatchedFiles` 与文件操作通知使用同一套项目刷新流程，能清除受影响项目中的跨文件编译诊断，并更新推送或拉取诊断。客户端支持动态监听时，服务器监听来源、图片的内容变化，以及任意文件名的创建和删除；图片后缀不区分大小写。已知来源或图片在编译期间实际改变时会取消当前及排队任务；延迟送达的重复监听通知不会取消正在编译相同已保存内容的任务，也不会清除仍与已编译输入一致的历史诊断；拉取诊断的内容和版本未变时保留结果 ID。每个项目分别保存已发布诊断对应的输入快照，共享文件更新后只清除使用旧内容的项目；新编译的输入快照不会覆盖旧诊断的依据。源码和二进制输入均按内容检查，不依赖修改时间或文件大小；图片等二进制内容使用流式指纹，支持保留时间和大小的替换，未通知的编译期间修改也会使结果过期。只检查存在性的数据内容更新不会取消编译，也不会通过监听通知进入符号索引。

服务器读取本次编译新增或更新的 `.blg` 文件，分析 BibTeX 的重复条目、语法错误和字段警告，以及 Biber 的错误/警告；能识别数据库和文献键时定位到 `.bib` 文件。未能定位的消息显示在主文档。旧 `.blg` 不会被当成本次编译错误。日志中实际读取的 `.bib` 和 `.bst` 也会加入项目依赖，支持宏展开后的文献路径、文献键重命名、根文件识别、未保存检查和过期 PDF 检查；系统目录中的样式不会批量索引。文献记录独立于 `.fls` 保留，直到新的文献日志更新它，避免只运行 TeX 时丢失文献来源。

BibTeX 报告无法打开样式文件时，诊断代码为 `missing-bibliography-style`。最终 TeX 日志确认读取的来源中只有一个对应的静态 `bibliographystyle` 声明时，错误定位到精确样式名，并提供最多 5 个同目录本地 `.bst` 拼写建议；保留逗号名称、显式后缀和周围注释。动态或拼接名称、声明歧义、来源不完整及扫描超限时保留主文档中的错误，不提供猜测修复。样式已经恢复或诊断过期时不再修复。

BibTeX 无法打开数据库时，诊断代码为 `missing-bibliography-database`。实际读取的项目源码中存在唯一静态 `bibliography` / `nobibliography` 声明时，精确标出列表中的缺失项，提供最多 5 个同目录本地 `.bib` 拼写建议；保留其他数据库、注释、目录及显式后缀。按 BibTeX 规则匹配名称中的空白，候选不引入空白或逗号。系统宏包实现不充当用户声明，本地宏包、文档类及已索引的外部来源仍参与校验；动态名称、重定义、歧义、来源不完整或日志截断时保留主文档错误，不提供猜测修复。修复兼容版本化编辑和旧客户端，并在应用前复查版本与文件是否已恢复。

默认 latexmk 确认数据库缺失并跳过 BibTeX 时，服务器也会产生 `missing-bibliography-database` 警告，提供相同的精确定位和修复。编译继续遵守 latexmk 的策略及现有输入一致性检查，预生成 `.bbl` 的项目仍可生成 PDF。警告只采纳本次最后一次目标日志检查后的完整驱动列表，已有的原生 BibTeX 错误优先；没有输出新列表的空操作编译不会新增缺库警告。其他可执行程序、不同作业日志、不完整或截断的输出不进入这项解析。

文献依赖和日志定位共用搜索规则，识别 BibTeX 的工作目录与 latexmk 报告的数据库/样式搜索路径，避免主目录和输出目录中的同名文件导致定位错误。Biber 日志中的空格、中文及含单引号的数据库名也会保留。

TeX 可能在缺少 `\include` 章节时仍生成 PDF 并返回成功。服务器会把 `No file chapter.tex.` 转为 `missing-include` 警告，识别并标出调用文件中的静态章节路径；支持长路径自动折行，补回文件并重新编译后清除。正常首次编译时缺少 `.aux` / `.bbl` 的消息，以及无法关联到章节声明的可选文件消息不会作为章节警告。日志和编译输出中被 TeX 按字节换行拆开的 UTF-8 字符会先恢复，保留中文等路径和对应文件的诊断位置。

编译开始时尚未找到的静态 `\include` 章节也参与存在性追踪。章节在编译期间补回时，即使没有文件通知，也会丢弃旧诊断并将结果标为过期；创建文件或其目录的通知会取消相关编译及队列。已完成编译的缺章警告会在补回通知后清除，未重写的旧 PDF 和 SyncTeX 映射仍要求重新编译，保存了旧修改时间的文件同样如此。静态 `\includeonly` 排除的章节不参与这项缺失追踪；选择名称可带 `.tex`，也可来自已加载的设置文件。选章含宏展开或多次声明无法一致确认时，跳过缺章追踪，不推断执行顺序；已有来源的内容检查和 recorder 规则继续生效。候选路径与条件文件共用前述追踪及缓存上限。

缺失图片的精确诊断代码为 `missing-image`，`data.file` 保留实际文件名；支持 pdfLaTeX、XeLaTeX、LuaLaTeX 的错误消息、中文与空格路径，以及跨行参数。最多提供 5 个相近图片名，保留目录前缀并使用实际扩展名；只搜索编译根目录和该项目的静态 `\graphicspath`。存在宏展开、日志上下文不匹配或来源无法确认时保留整行诊断，不提供路径替换；过期诊断或已恢复的图片也不会触发修复。

Overfull/Underfull 诊断会覆盖日志中 `at lines N--M` 指定的完整源码范围，并分别标记 `overfull-box` / `underfull-box` 诊断代码；支持 UTF-16 和 CRLF，异常范围会限制在文档内。

字体替换、文档类和引擎警告，以及 `Missing character` 缺字消息也会显示为警告，即使编译成功生成了 PDF。支持换行消息，避免把相邻错误并入上一条警告；没有来源行号的消息显示在当前文件第一行，重复的同位置消息合并显示。

pdfLaTeX 和 LuaLaTeX 的缺失 PDF 目标警告会定位到本次编译来源中的静态 `hyperlink` / 内部四参数 `hyperref`，诊断代码为 `undefined-pdf-destination`，`data.destination` 保留实际目标名。支持宏展开后由 recorder 发现的子文件，并合并同位置的重复警告；恢复引擎按字节折行的长目标名和说明文字，保留实际空白，不吞并后续字体资源输出。无法确认名称或源码引用时保留原警告位置。不会根据静态索引的缺失自行报警，章节等自动目标仍由编译器判断。精确诊断提供当前项目内最多 5 个 PDF 目标拼写建议，与普通标签分开；修复组合目标时保留两个参数之间的注释、括号和换行，兼容旧客户端并拒绝过期修复。

两个引擎的重复 PDF 目标警告也会定位到本次编译来源中的静态 `hypertarget` / `hyperdef` 声明，诊断代码为 `duplicate-pdf-destination`，`data.destination` 为目标名称；关联信息列出同次编译中最多 16 处其他显式声明。支持长名称、组合目标和跨文件定位，保留无法关联的原始警告；pdfLaTeX 将过长名称缩写为 `\ETC.` 时，不根据前缀猜测目标。显式目标与章节自动生成的目标冲突时，也能根据真实编译警告标出显式声明；同名标签和链接文字不参与声明定位。此类诊断不提供拼写替换；消除显式声明的歧义后，可使用现有重命名功能调整目标名及其链接，再编译确认冲突消失。

没有源码行号的 PDF 目标警告，其跨文件定位、关联信息和拼写候选限于根文档及最终 TeX 日志确认读取的项目来源。recorder 也可能记录仅检查存在性的选章外文件，这些文件仍参与已有依赖和产物检查，但不会仅凭 recorder 记录收到目标诊断或作为 PDF 目标修复候选。重新编译会更新读取范围；日志截断或缺少读取记录时，只使用能够确认的来源。

`.aux`、`.bbl`、`.toc`、`.lof`、`.lot`、`.out`、`.nav`、`.snm` 和 `.vrb` 中的编译错误或警告定位到实际生成文件，支持传统错误、显式文件行号、空格/中文路径和长路径折行；这些文件仍不进入项目来源索引。若 LaTeX 报错后重写文件，导致原行号已不存在，诊断保持有效位置，并在消息及 `data.reportedLine` 中保留原始行号。

Neovim 中可这样触发编译：

```lua
vim.lsp.buf_request(0, 'workspace/executeCommand', {
  command = 'latex.build',
  arguments = { vim.uri_from_bufnr(0) },
}, function(err, result)
  if err then vim.notify(err.message, vim.log.levels.ERROR)
  else vim.notify('LaTeX: ' .. result.status) end
end)

vim.lsp.handlers['latex/buildFinished'] = function(_, result)
  local level = (result.status == 'success' or result.status == 'cancelled')
    and vim.log.levels.INFO or vim.log.levels.ERROR
  vim.notify(result.message, level)
end
```

根文件优先级为：配置的 `rootFile` → 文件前 20 行的 `% !TeX root = ../main.tex` 指令（支持链式解析并检查循环）→ 包含当前子文件的唯一主文档 → 当前 `.tex` 文件。有多个主文档时需要显式指定根文件。

### 编译配置

使用 `initializationOptions`（Neovim 的 `init_options`）设置，运行中也可发送 `workspace/didChangeConfiguration`，其 `settings` 可直接使用下列对象或包在 `latex` 字段内。无效配置会被拒绝并保留原配置。

```json
{
  "build": {
    "executable": "latexmk",
    "arguments": null,
    "rebuildArguments": null,
    "engine": null,
    "outputDirectory": "build/latex-lsp",
    "rootFile": null,
    "onSave": false,
    "timeoutSeconds": 120
  }
}
```

`rootFile` 相对于当前工作区根目录，`outputDirectory` 相对于主文档所在目录。`executable` 可改为 `pdflatex`、`xelatex`、`lualatex` 或 `tectonic`，省略 `arguments` 时自动选择对应的默认参数。自定义参数中的 `%f` 替换为根文件绝对路径，`%o` 替换为输出目录，`%j` 替换为产物名称（未配置时为主文件名去掉扩展名）；参数直接传给进程，不经过 shell。默认 TeX/latexmk 参数关闭 shell escape。超时范围为 1–3600 秒。

`build.rebuildArguments` 单独指定强制编译的完整参数列表，也支持 `%f`、`%o`、`%j`；普通 `latex.build` 仍使用 `arguments`。自定义了 `arguments` 或使用未知编译工具时，必须显式设置 `rebuildArguments` 才能调用 `latex.rebuild`，否则在修改旧日志前报错。例如自定义 latexmk 参数时，可设 `"rebuildArguments": ["-g", "-pdf", "-interaction=nonstopmode", "-file-line-error", "-synctex=1", "-no-shell-escape", "-outdir=%o", "%f"]`；参数应包含工具所需的完整编译选项，设置 `jobName` 时也需自行传入 `%j`。使用这份自定义参数的重编译通知中，`engine` 为 `null`。

例如 Neovim 配置中可加入 `init_options = { build = { executable = 'xelatex', onSave = true } }`。手动使用 XeLaTeX/pdfLaTeX 时只运行一遍，需要多遍处理文献和交叉引用的项目建议使用 latexmk，并自行配置对应引擎参数。

`build.jobName` 可设置 PDF、日志、recorder 和 SyncTeX 的共同文件名，例如 `"jobName": "论文 draft.v2"` 生成 `论文 draft.v2.pdf`，主文件仍可以叫 `main.tex`。latexmk 和三个直接 TeX 引擎会自动添加 `-jobname`；自定义 `arguments` 需自行传递 `%j`。名称支持字母、数字、空格、点、下划线和短横线，不能包含目录或前后空格。Tectonic 默认调用不支持该选项。开始和完成通知的 `jobName` 返回实际产物名称；两个项目若将写入同一个 PDF，会拒绝并行编译，待前一次结束后可再次编译。

使用 latexmk 时，`engine` 可设为 `pdflatex`、`xelatex` 或 `lualatex`，服务器会选择相应的多遍编译模式。未指定时，优先读取主文件前 20 行的 `% !TeX program = xelatex` 或 `% !TeX TS-program = lualatex`，否则使用 pdfLaTeX；指令忽略大小写和逐字环境，只接受这三个引擎名称。子文件中的 program 指令不会覆盖主文件。显式 `engine` 优先于指令，显式选择的直接引擎 `executable` 和自定义 `arguments` 保持其调用方式。例如 `init_options = { build = { engine = 'xelatex', onSave = true } }` 可用 latexmk 自动处理 XeLaTeX 的多遍编译及文献。

### SyncTeX 双向查询

成功编译后，安装的 `synctex` 命令行工具可提供源码与 PDF 之间的映射。通过 `workspace/executeCommand` 调用：

```json
{
  "command": "latex.forwardSearch",
  "arguments": [{
    "uri": "file:///project/chapter.tex",
    "position": { "line": 12, "character": 4 }
  }]
}
```

返回 `{rootUri, pdfUri, locations: [{page, x, y, h, v, width, height}, ...]}`。源码 `position` 遵守 LSP 的零起始 UTF-16 约定，查询采用行级映射；PDF `page` 从 1 开始，`x` / `y` 从页面左上角计量，单位为 1/72 英寸。可选的 `h` / `v` / `width` / `height` 描述所在排版框。

```json
{
  "command": "latex.inverseSearch",
  "arguments": [{
    "uri": "file:///project/main.tex",
    "page": 1,
    "x": 150.0,
    "y": 135.0
  }]
}
```

反查也用源文件 `uri` 识别项目，返回 `{rootUri, pdfUri, locations: [Location, ...]}`，其中 `Location` 是可交给编辑器跳转的标准 LSP 位置，范围位于对应行首。查询可能返回多个候选或空列表，服务器不会自动启动 PDF 阅读器或编辑器。查询在后台执行，最多同时运行 4 个，每次最多运行 5 秒、返回 256 项；期间仍可编辑和发送其他请求。标准 `$/cancelRequest`、超时和 shutdown 会终止查询进程及其子进程，返回前会再次检查来源和产物；PDF 和映射文件在查询期间等长替换且保留时间戳时，也会丢弃该次结果，这项查询前后检查在服务器尚未编译过项目时同样生效。要求输出目录内已有 PDF 和 `.synctex.gz` 或 `.synctex`。项目存在未保存内容、来源晚于同步记录，或者当前编译运行中/最近编译未成功时，会要求保存并重新编译。

## 开发

```sh
cargo fmt --all -- --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
# 已安装 latexmk、pdfLaTeX、XeLaTeX、LuaLaTeX、BibTeX、SyncTeX 和 Neovim 0.10+ 时，执行真实编译及编辑器测试：
cargo test --locked -- --include-ignored
```

开发和测试构建默认关闭调试信息与增量缓存，以控制磁盘占用。需要源码级调试时，可按需设置 `CARGO_PROFILE_DEV_DEBUG=2` 或 `CARGO_PROFILE_TEST_DEBUG=2`；发布构建继续使用独立配置。

测试包含 UTF-16/增量编辑、语法容错、跨文件导航、文献补全、磁盘/未保存内容同步，以及启动真实进程验证的 stdio 协议流程。

同一次编译日志中的重复颜色、颜色模型、计数器、环境及缺失输入文件、宏包、文档类错误会复用当前来源集合的宏签名和各类文档调用分析，减少大文档多错误时的重复解析。缓存只保留最近的宏来源集合及每类错误的一份文档分析；来源集合变化时重新分析，每条错误仍核对源码内容，不跨编译保留缓存。

代码按职责拆分：`text.rs` 处理位置与编辑，`syntax.rs` 解析 LaTeX/BibTeX，`workspace.rs` 管理文件索引与根文档，`features.rs` 实现语言功能，`signature.rs` 提供命令参数提示，`navigation.rs` 处理工作区搜索、折叠和链接，`editing.rs` 处理快速修复、高亮和选择范围，`file_operations.rs` 维护文件移动后的引用，`build.rs` 管理后台编译，`build_log.rs` 分析日志，`recorder.rs` 读取实际输入记录，`synctex.rs` 查询源码/PDF 映射，`config.rs` 校验配置，`dispatch.rs` 保留消息顺序并释放耗时查询的等待，`lib.rs` 对接 LSP，`main.rs` 启动服务。

## 当前范围

这是可运行的基础版本，使用静态解析，不执行 TeX 宏展开或读取 TeX 发行版的包数据库。自定义命令支持 `\newcommand`、`\renewcommand`、`\providecommand`、`\DeclareMathOperator`、`\DeclareRobustCommand` 和 xparse 的 `\NewDocumentCommand` 等声明，包含花括号与直接控制序列形式；也识别 `\def` / `\gdef` / `\edef` / `\xdef` 和 `\let`。BibTeX 支持常见 `{...}` / `(...)` 条目和嵌套字段。

自定义环境支持 `\newenvironment` / `\renewenvironment`、xparse 的 `\NewDocumentEnvironment` 等声明、`\NewEnviron` / `\RenewEnviron` 和 `\newtheorem`，提供补全、定义跳转、引用、悬浮、符号及跨文件重命名。改名时同步维护 `\begin{panel}` / `\end{panel}`、直接调用的 `\panel` / `\endpanel` 和字面 `\csname panel\endcsname`；可从这些调用处跳转或发起重命名。检查环境生成的同名宏和 `\end...` 宏，避免与已有命令冲突；存在直接控制序列调用时，新名称须只含 TeX 命令字母。

普通自定义宏也支持字面 `\csname hello\endcsname` 的定义跳转、悬浮、引用、高亮和重命名，与直接调用的 `\hello` 统一处理；保留 `csname` 控制词后的词法分隔空白及调用参数。识别 `\expandafter\def\csname hello\endcsname#1{...}`、同样写法的 `gdef` / `edef` / `xdef`、`newcommand` / xparse 系列以及 `let` 别名定义；可从字面定义处发起重命名，参数提示与直接定义一致。字面调用可提示内置命令、自定义宏和环境参数，签名保留 `\csname ...\endcsname` 写法。名称中的宏展开、注释拼接、语义空白和未闭合的 `csname` 不作推断，也不会误记为重新定义 `csname` 原语；共享调用在不同项目里指向不同宏时拒绝重命名。

用户宏参数提示识别 `\newcommand` 系列和 `\DeclareRobustCommand` 的参数数量/首个可选参数默认值，xparse 的 `m` / `o` / `O{...}` / `s` / `t+` / `d<>` / `D<>{默认值}` / `r()` / `R(){默认值}`，以及 `\def` 系列连续的 `#1#2...` 参数。传统宏及环境的可选参数和默认值在首个未受花括号保护的 `]` 处结束，保留字面量 `[`；xparse 调用仍匹配嵌套方括号。直接调用、`csuse` 和静态 `csname` 使用所调用命令的规则，支持星号、嵌套调用、转义和多行注释。`t` 标志支持字符、控制序列及 Unicode token，保留有无标志时的后续参数编号；分隔参数支持字符、控制序列和 Unicode 分隔符，匹配嵌套、花括号保护及完整 token；缺失必需分隔符时保守回退。不支持的参数规格、字符串求值或定义有歧义时暂不推断签名；不在注释和逐字文本中提示。

零参数宏的分组正文若只含一个控制词，参数提示和命令补全也会沿当前项目内的静态别名链继承目标签名，显示所调用的别名及其声明位置。支持传统声明、TeX 定义、命名定义和 xparse 空参数规格，允许正文外围注释和空白；补全只插入必需参数，保留已有可选参数、标志和分隔参数。循环、未知目标、重定义、展开式定义及其他正文不推断转发签名；空宏和无参开关不生成参数片段。

必需参数也支持未加花括号的单个 ASCII 字符、控制词、控制空格和转义符号，例如 `\pair a{body}`、`\pair\payload{body}` 和 `\frac12`。直接调用、`csuse`、静态 `csname` 和环境使用相同的 token 边界，并保留后续 `!` 参数的词法空白规则。未分组的 Unicode、`^^` 字符转义和显式 `\par` 暂不推断为单个实参；花括号内的 Unicode 正常支持，避免混淆 pdfTeX 的 UTF-8 字节与 XeTeX 的字符分词。引用范围的标签端点仍要求花括号分组，保持与导航、重命名的识别规则一致。

普通 xparse 命令及环境的末尾可选参数支持 `!` 修饰符：有效空格会结束参数读取，紧邻注释及控制词后的词法空白按 TeX 规则处理，空行保留段落边界；`csuse`、直接环境调用及 `begin` 各自保持实际读取方式。无效的 `!` 位置和可展开声明中的该修饰符不推断签名。例如规格 `m !o` 下，`\probe{body}[note]` 会读取可选参数，而 `\probe{body} [note]` 的方括号属于正文。

支持 snippet 的客户端补全用户宏时，还会按同一签名生成必选参数的 tabstop。例如 `\newcommand{\pair}[2][blue]{...}` 会补成 `\pair{...}`，保留首个可选参数的默认值；xparse 星号、`t` 标志及可选分隔参数也默认省略，必需分隔参数保留分隔符，并正确转义 snippet 特殊字符及隔开控制词。宏后已有分组、标志、分隔参数，或同一逻辑行上的无花括号 ASCII 实参时仅替换命令名，保留注释续行；普通换行后的正文不会抑制参数占位符。客户端不支持 snippet 或签名无法安全推断时，继续提供命令名补全。

文献条目间引用支持 `crossref`、`xref`、`xdata`、`related` 和 `entryset`，包含花括号或双引号形式，以及后三类字段的逗号分隔列表；可补全、跳转、查找引用、高亮和重命名父条目。字段名不区分大小写，补全也支持尚未闭合的值。字符串宏、`#` 拼接或含 TeX 命令的值需要求值，暂不自动修改；标题和注释中的同名文本会保留。文献键不能重命名为 `*`，以免改变 `\nocite{*}` 的全选含义。

目前不内置 PDF 预览、格式化或数学语义检查；默认编译生成 SyncTeX 数据，可由预览插件接入双向查询。未定义引用的即时静态检查暂不报错，编译器提供的相关警告会显示在诊断中。定义和引用在整个工作区索引中查找；重命名要求该名字在索引中只有一个定义，存在歧义时会拒绝操作。内置命令不支持重命名。

文件/目录重命名需要编辑器或文件管理插件发送 `workspace/willRenameFiles` 并应用返回的编辑，然后移动文件并发送 `workspace/didRenameFiles`。服务器会保留打开文档的版本、刷新磁盘索引，并停止使用旧输入路径的编译；不会自行移动文件。含 TeX 宏的路径无法静态解析，新路径含无法安全表达的特殊字符时会拒绝引用更新；显式配置的 `build.rootFile` 需在主文件改名后同步修改。 输入源码改为其他扩展名时会保留新后缀，例如 `\input{chapter}` 在 `.tex` 改为 `.ltx` 后更新为 `\input{chapter.ltx}`，根指令同步更新；`\include` / `\includeonly` 章节需要保留 `.tex`，通过包/文档类加载命令使用的文件需要保留 `.sty` / `.cls` 后缀，本地 BibTeX 样式需要保留 `.bst`，通过 `\bibliography` 使用的文献库需要保留 `.bib`。

重命名静态 `\newtheorem{claim}{Claim}` 时，同步维护 `\newtheorem{lemma}[claim]{Lemma}`、`\newtheorem{fact}{Fact}[claim]`、`\newcounter{inner}[claim]`、常见计数器操作与 `counterwithin` / `counterwithout` / `numberwithin`，以及 `\claim`、`\endclaim`、`\theclaim` 等派生命令；支持字面 `\csname theclaim\endcsname`，不展开动态宏。共享计数器的定理保留底层计数器，无编号定理不修改独立计数器。新名称与计数器或派生命令冲突、或共享引用属于其他项目中的独立计数器时拒绝改动；存在直接派生命令调用时，新名称需能组成 TeX 控制序列。

磁盘索引最多 1024 个文件、单文件 2 MiB、目录深度 16，跳过隐藏目录、构建目录和目录符号链接；编辑器主动打开的文件不受磁盘文件大小限制。相对路径的文件引用还会按最多 16 层递归载入根目录外的依赖。支持动态文件监听的客户端会自动注册监听；其他客户端需发送 `workspace/didChangeWatchedFiles` 才能更新未打开文件的磁盘变化。
